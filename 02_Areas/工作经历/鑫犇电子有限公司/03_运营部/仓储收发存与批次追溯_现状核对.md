## 七、现有库存与批次表能复用什么，如何避免重复台账

### 可复用部分（候选判断）

1. **主流水候选：**优先验证生产工作簿的“库存与批次”能否承接一条物料或产品从来源/去向到数量、单位、状态、库位、工单的记录。
2. **来料节点：**复用运营“采购与来料”作为供应商、到货、材料批次、检验状态和入库状态的来源记录，不再抄建一份“收货批次表”。
3. **领料节点：**复用“领料核对”作为工单—材料规格—材料批次—领料/余料重量—标签—核对结果的生产领料证据，不另建领料台账。
4. **成品放行节点：**复用“出货放行”作为订单—成品批次—数量—检验记录—包装/标签—放行结论的品质/运营证据；库存减少是否由现有库存与批次记录承接，需真实记录验证。
5. **状态与识别线索：**材料主数据、产品主数据和易混材料可作为识别/校对来源，但照片整理或空白主数据不能直接视为已批准依据。

### 避免重复台账的原则（候选，不是指令）

- 先确定一个主记录入口和各节点证据，不把同一批次在仓储、采购、生产各自重复抄写成三套“余额”。
- 先查同一条真实记录在“采购与来料”→“库存与批次”→“领料核对”/“出货放行”之间是否能用材料编码、产品编码、批次、工单或订单串联。
- 若只是缺少“收发类型、关联记录编号或状态更新时间”等连接信息，优先讨论在现有文件内的最小补充；不得在本核对阶段自行改 Excel。
- 只有确认现有表无法承接不同粒度的事实，且重复维护风险可接受时，���讨论新增载体；当前不作该结论。

## 八、不造样本的微型验证：查一笔真实收发 / 库存批次

**验证目的：**只判断现有记录能否把一次真实收货或领料/退料与库存批次、状态和下游使用串起来；不判断整体库存准确率，不证明流程能力，不制造一笔样本。

### 推荐取样方式

1. 由已确认的相关负责人指定 **1 笔近期真实收发或库存批次记录**。优先选择能找到采购来料、库存与批次、领料核对或出货放行中至少两类证据的一笔；不使用 `EX-示例`，没有真实记录就明确记录“未找到”，不人为补造。
2. 若选真实来料：从“采购与来料”的记录编号/材料编码/批次出发，查到实物标签、检验状态、入库状态、库存与批次中的数量/单位/状态/库位，并核对是否进入过领料或退料记录。
3. 若选真实领料：从“领料核对”的记录编号/工单/材料批次出发，反查库存与批次的来源、状态、库位和数量，再核对生产任务的材料规格及余料/退料去向（如有）。
4. 若选真实成品：从出货放行的订单/产品/批次/检验记录出发，查库存与批次中的入库/状态/数量/库位及工单；若没有成品入库记录，明确标为断点，不用推断补齐。
5. 只记录：找到的原始证据位置、找不到的节点、字段冲突、状态是否一致、查找耗时/反复查找点、需要谁确认的事实。不得把补查笔记写成正式收发凭证或放行结论。
6. 由确认的复核人决定：现有“库存与批次”能否作为主入口；采购、生产、品质、运营各表是否只是节点证据；是否需要最小连接说明；是否继续查另一类真实记录。

### 验证结果的判定边界

- 找到一笔链路，只能说明该笔可以被核对，不能代表所有库存准确或所有批次可追溯。
- 找不到真实记录，只能说明本次尚未取得证据；不能据此断言现场没有收发或库存管理。
- 任何状态值、责任人、放行人、盘点规则和差异处理方式，均要以实际记录或管理层确认作为依据，不凭字段名称推断。

## 九、需确认的最小责任 / 权限

只确认执行所必需的边界，不预设具体人名或岗位授权：

1. **收发责任：**谁负责收货点数/称重、记录供应商与批次，谁负责领料/退料/成品出入库的实物交接与记录。
2. **状态更新：**谁更新“待判、合格可用、不合格/隔离、已领用、退料、成品待检/已放行”等实际状态；状态改变依据和时间如何留下证据。
3. **隔离/放行：**谁可以将物料或产品标为待判/隔离；谁能解除隔离、批准入库、批准领用或放行出货；不得把“记录人/确认人”字段自动等同于授权人。
4. **数量与差异：**收货、领料、退料、成品入库和盘点出现数量/重量差异时，谁先复核，谁决定暂缓使用，谁向采购/生产/品质/运营或管理层升级。
5. **批次追溯复核：**谁负责用真实记录回查一条批次链，谁判断现有表够用、哪里是断点及是否需要最小补充。
6. **盘点（如实际存在）：**谁发起、谁执行、谁复核账实差异，谁批准差异原因和后续处理；如果目前没有盘点机制，需明确为未知，不先设定周期或责任。

上述事项完成确认前，不写死仓储组、采购、生产或品质的职责分配，不生成 RACI，不发布流程。

## 十、按丰田式骨架的最小下一步（候选）

1. **目标状态 / 价值：**一笔物料或成品从收货/入库到领料、退料、成品入库和出货，能按批次、数量、状态、库位、工单/订单回查；待判/隔离不会被误用，差异能及时升级。价值是减少错料、混批、漏记、账实差异和异常时无法界定影响范围。
2. **当前状态：**现有文件分散承接采购来料、库存与批次、领料、生产任务、出货放行等字段；仓储组和采购目录本次未发现独立可核验文件，模板示例/空行不能证明现场执行。
3. **差距与障碍：**收发类型、成品入库、退料、状态更新时间、实物交接、隔离/放行权限和盘点差异字段/记录位置未知；跨表连接键和主记录入口未确认，存在重复台账或库存状态不同步风险。
4. **选择适当确认方式：**先查一笔已有真实收发或库存批次记录；只有当记录不能解释某个断点时，再找实际相关岗位走查该笔，不机械先建表或先写 SOP。
5. **对策 / 实验：**不改 Excel、不新增模板；用现有“库存与批次”作为待验证主入口，联查“采购与来料”“领料核对”或“出货放行”，记录可追溯节点、断点和重复录入点。
6. **责任与期限：**由管理层确认本次微型验证的牵头人、提供记录者、状态确认者、隔离/放行权限人和完成期限；在确认前不指定个人或岗位。
7. **证据复核：**复核人回读原始记录、实物标签/凭证（如可取得）、批次、数量、状态、库位、工单/订单关联及差异处理；明确哪些是文件事实、哪些是现场未知。
8. **固化或继续改善：**若一笔真实记录能稳定串联且权限清楚，才讨论在现有文件内最小固化连接方式；若仍断链、状态冲突或职责不清，继续改善和确认，不新建重复台账、不发布制度。
