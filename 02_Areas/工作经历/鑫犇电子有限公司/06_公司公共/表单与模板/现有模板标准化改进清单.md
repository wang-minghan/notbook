# 现有模板标准化改进清单

> 本清单仅基于现有模板的工作表名称和字段进行检查，提出最小必要的增量改进建议；不等同于已实施制度、审批权限或字段最终定版。
>
> 原则：在原模板内补字段、补说明或统一标识；不新建体系目录，不创建平行模板，不把建议写成已实施制度。示例行均应继续保持“虚拟示例/不可用于生产”的标识。

## 一、生产部

### 1. 生产车间

- **现有模板**：`01_生产部/生产车间/生产与物料模板.xlsx`
- **现有工作表与字段概览**：
  - `材料主数据`：材料编码、材料牌号、状态/硬度、厚度、宽度、供应商编码、材料批次、入库日期、库存重量、标签状态、状态、备注。
  - `库存与批次`：记录编号、日期、物料/产品编码、名称、客户、批次、来源/去向、数量、单位、状态、库位、关联工单、记录人、备注。
  - `产品主数据`：产品编码、客户名称、产品名称、现场常用名、产品型号、图号、图纸版本、材料牌号、材料厚度/宽度、单重参考、模具编号、状态、生效日期、备注。
  - `易混材料`：对照编号、产品编码、客户、产品、型号、正确材料牌号、厚度/宽度、易混对象、主要区别、核对依据、混用后果、状态、备注。
  - `生产任务`：确认单号、生产日期、班次、工单号、产品编码、客户/产品信息、图号与版本、计划数量、交期、材料规格、模具/设备编号、上次异常、三项一致确认、确认人等。
  - `领料核对`：记录编号、日期、工单号、产品编码、材料规格、材料批次、领料重量、余料重量、标签状态、核对结果、核对人、备注。
- **已覆盖事项**：材料与产品主数据、批次和库位追踪、易混材料防错、生产任务下达、工单与图纸版本关联、模具/设备关联、领料和余料核对。
- **最小必要补充（建议）**：
  1. 在`生产任务`增加“任务状态/完工数量/报工日期（或时间）/实际异常编号”中的必要字段，先由生产确认最小集合。
  2. 在`库存与批次`和`领料核对`统一“数量/重量单位”和“状态”取值说明，并保留关联工单字段。
  3. 对产品、材料、图纸版本、模具和设备编号增加“唯一编码来源/维护责任”说明，不新增独立主数据表。
  4. 将“三项一致确认”明确为可填写的核对结果（而非仅文字提示），并补“异常时关联编号”字段或备注规则。
- **与其他部门的接口**：
  - 与运营部`客户订单台账`、品质部`客户订单评审`按订单号/评审编号、产品编码、客户、交期衔接。
  - 与运营部`采购与来料`按供应商编码、材料编码、材料批次、数量和检验/入库状态衔接。
  - 与品质部`首件检查`、`过程巡检`、`不合格与异常`按工单号、产品编码、材料批次、模具编号、工位号衔接。
  - 与模具维修组`试模记录`、`修机报告`按模具编号、设备编号、工位号、试模/维修编号衔接。
- **暂不能确认的字段/权限**：生产任务由谁最终确认、计划数量与实际报工的责任边界；库存重量是否由仓储或生产维护；“三项一致”的三项具体定义；班次、状态、单位的标准取值；产品/材料/图纸版本的主数据维护权；异常关闭和放行权限。

### 2. 模具维修组

- **现有模板**：`01_生产部/模具维修组/模具与维修模板.xlsx`
- **现有工作表与字段概览**：
  - `模具台账`：模具编号、产品编码、模具名称、当前版本、设备适配、累计使用量、保养日期/计划、状态、责任人ID、资料位置、备注。
  - `模具零件`：零件ID、模具编号、工位号、零件名称/类型、材料、热处理要求、尺寸特征、装配位置、图纸号/版本、备品数量、存放位置等。
  - `试模记录`：试模编号、日期、模具/产品/材料/设备/工位、问题位置与现象、调整内容、调整前后数据、单位、样件结果、后续处理、记录人、确认人、状态、备注。
  - `修机报告`：报告编号、报修日期、模具/产品/工位、故障现象、停机时数量、隔离范围、测量数据、原因、处理方式、更换零件ID、维修前后照片路径、试模编号/结果、后续提升、维修人、确认人、关闭日期。
  - `模具备品`：库存记录号、零件ID、模具编号、工位号、零件名称、最低/当前库存、单位、存放位置、入库/领用日期、补充状态、负责人、备注。
- **已覆盖事项**：模具和零件台账、图纸版本、设备适配、保养计划、试模调整记录、维修及隔离、照片证据、备品库存和补充状态。
- **最小必要补充（建议）**：
  1. 在`模具台账`补“当前所在位置/借用或占用状态”，避免仅凭资料位置判断实物状态。
  2. 在`修机报告`补“关联异常编号/工单号”和“复机确认条件”，使维修记录能回接质量与生产记录。
  3. 在`试模记录`补“样件送检/确认记录编号”（如确有该流程），不在本表重复质量检验字段。
  4. 统一编号格式、状态取值和照片路径填写规则；保留现有字段，不另建维修模板。
- **与其他部门的接口**：与生产车间按模具编号、产品编码、设备编号、工位号、工单号关联；与品质部按异常编号、试模结果、隔离范围和复机条件关联；与后勤固定资产仅在设备/资产责任和位置信息需要核对时衔接；与人事能力矩阵按岗位/人员的维修能力确认衔接。
- **暂不能确认的字段/权限**：模具保养触发依据是日期、使用量还是两者；维修报告的最终关闭人；试模样件由谁判定合格；照片存储位置和访问权限；零件图纸版本的批准人；备品最低库存和采购触发权限；“修机”是否仅指模具维修还是也包含设备维修。

## 二、品质部

- **现有模板**：`02_品质部/质量管理与检验模板.xlsx`
- **现有工作表与字段概览**：
  - `客户订单评审`：订单号、日期、客户、产品编码、图号/版本、数量、交期、材料标准、模具/设备、质量/包装/标签要求、评审结论、风险与措施、评审人、批准人。
  - `质量目标与月报`：周期、指标、目标/实际值、单位、趋势、异常/原因、措施、责任人ID、验证日期、状态、备注。
  - `改善与审核`：改善/审核编号、类型、日期、来源异常/客户、问题、原因、措施、责任人ID、截止日期、验证证据、效果验证、状态、关闭日期、备注。
  - `首件检查`：记录编号、日期、工单/产品、图号与版本、材料、检查项目、图纸标准、实测值、单位、检具、结果、检查人、确认人、备注。
  - `过程巡检`：记录编号、日期、工单/产品、检查时间、累计数量、项目、标准、实测值、单位、外观结果、异常、处理结果、检查人、备注。
  - `不合格与异常`：异常编号、发现日期时间、工单/产品、模具/工位、异常类别/现象、发现时数量、隔离范围、临时处理、原因、措施、恢复条件、处理结果、记录/确认人、关闭日期、状态。
- **已覆盖事项**：订单质量评审、质量目标跟踪、首件与过程检验、不合格隔离、异常处理、改善/审核和效果验证闭环。
- **最小必要补充（建议）**：
  1. 统一质量异常、改善/审核、首件、过程巡检之间的关联编号字段，优先补“来源编号/关联编号”，不增加新的异常表。
  2. 在`首件检查`和`过程巡检`增加“检验依据版本/检具编号（必要时）”的填写说明，防止标准和实测值无法追溯。
  3. 在`不合格与异常`明确“隔离范围、放行/恢复条件、放行依据”的最小填写要求；是否增加独立“放行人”字段待确认。
  4. 将`改善与审核`的“效果验证”与验证证据区分为结论和证据位置/编号，避免只填一句描述。
- **与其他部门的接口**：与运营部订单、供应商和出货记录按订单号、产品编码、批次、评审编号、检验记录编号衔接；与生产车间按工单号、材料批次、模具/设备/工位衔接；与模具维修按试模编号、维修报告编号和恢复条件衔接；与人事按岗位能力和培训记录衔接。
- **暂不能确认的字段/权限**：质量目标指标口径和数据来源；订单评审的批准层级；首件确认、异常关闭、出货放行是否必须由品质部独立执行；客户特殊要求的受控来源；检具校准/有效期是否纳入本模板；质量异常是否允许生产先行恢复；责任人ID对应的人员主数据来源。

## 三、运营部

- **现有模板**：`03_运营部/业务/订单与供应商模板.xlsx`
- **现有工作表与字段概览**：
  - `客户订单台账`：订单号、接收日期、客户、产品编码、数量、交期、客户特殊要求、订单状态、评审编号、业务负责人ID、交付风险、备注。
  - `供应商管理`：供应商编码/名称、主要物料、联系人（不填电话）、准入状态、质量/交期/异常响应评价、最近评价日期、责任人ID、异常记录/措施、备注。
  - `采购与来料`：记录编号、日期、供应商编码、材料编码/批次、采购/到货数量、检验状态、入库状态、关联工单、责任人ID、备注。
  - `出货放行`：放行编号、日期、订单号、客户、产品编码、批次、数量、包装/标签确认、检验记录编号、放行结论、放行人ID、备注。
- **已覆盖事项**：订单接收与交付风险、订单评审关联、供应商准入评价、采购到货和来料状态、出货包装标签与质量放行关联。
- **最小必要补充（建议）**：
  1. 在`客户订单台账`补“订单变更/版本标识”和“最近更新时间”（若业务存在变更），避免同一订单的特殊要求被覆盖。
  2. 在`采购与来料`补“采购单/到货单或外部凭证编号”中的实际必要项，并明确采购数量与到货数量单位。
  3. 在`出货放行`补“实际出货日期/交付状态”（如订单台账需要回写），不复制质量检验数据。
  4. 统一供应商编码、材料编码、订单号、批次号和检验记录编号的填写格式及来源说明。
- **与其他部门的接口**：与品质部订单评审、供应商评价、检验记录和放行结论衔接；与生产车间产品/材料主数据、生产任务和库存批次衔接；与后勤/行政仅在供应商资料和责任人员信息需要核对时衔接。
- **暂不能确认的字段/权限**：订单状态和交付风险的取值；订单变更由谁批准、是否允许业务直接修改；供应商准入与评价批准人；采购数量、到货数量、入库状态分别由谁维护；出货放行人与质量批准人的关系；客户特殊要求是否涉及受限信息及访问范围；供应商联系人是否还需其他合规字段。

## 四、行政部

### 1. 人事

- **现有模板**：`04_行政部/人事/能力与培训模板.xlsx`
- **现有工作表与字段概览**：
  - `岗位能力矩阵`：岗位ID、岗位名称、员工ID、员工姓名（可选）、技能/流程项目、能力等级、上岗状态、替代人ID、复核日期、确认人ID、备注。
  - `培训记录`：培训编号、培训日期、培训主题、关联流程编号、部门、员工编号/姓名、培训方式、考核结果、岗位确认结果、培训人、确认人、备注。
- **已覆盖事项**：岗位与员工能力映射、技能/流程项目、能力等级、上岗状态、替代人员、复核、培训和考核结果。
- **最小必要补充（建议）**：
  1. 统一`岗位能力矩阵`与`培训记录`中的员工ID、岗位ID、流程编号命名，优先保证可关联，不新增人员主数据表。
  2. 在培训记录补“培训材料/证据位置”和“下次复核日期”（若实际需要复训），避免只记录参加过培训。
  3. 对“能力等级、上岗状态、考核结果、岗位确认结果”增加简短取值说明，保留空白/待确认状态。
  4. 对员工姓名字段继续作为可选展示字段，原则上以员工ID为关联键，避免人员变动造成历史记录失真。
- **与其他部门的接口**：与各部门岗位、技能/流程与确认人衔接；与生产、品质、模具维修的上岗/替代资格核对；与行政后勤在员工和资产责任人信息需要核对时衔接。
- **暂不能确认的字段/权限**：能力等级的定义和评定人；谁可确认上岗；替代人是否必须具备同等级能力；培训记录的保存期限和查阅范围；员工ID、岗位ID的唯一来源；培训材料是否含客户或技术受限信息；离职/转岗后的历史记录处理权限。

### 2. 后勤

- **现有模板**：`04_行政部/后勤/固定资产模板.xlsx`
- **现有工作表与字段概览**：`固定资产`：资产编号、资产名称、资产类别、规格型号、使用部门、存放位置、责任人、启用日期、保养要求、当前状态、最近盘点日期、备注。
- **已覆盖事项**：固定资产识别、类别和规格、部门/位置/责任人、启用日期、保养要求、状态及盘点日期。
- **最小必要补充（建议）**：
  1. 增加“购置/来源凭证编号”（若财务或资产管理实际需要），不在本模板扩展财务台账。
  2. 增加“最近变更日期/变更事项”或在备注中规定记录调拨、报废、维修的最小格式，避免只更新当前位置。
  3. 对资产状态和盘点结果增加取值说明；若盘点需要差异处理，再补“差异/处理编号”，不新建平行表。
  4. 将“责任人”与人事员工ID关联的要求待确认后再定版，避免当前姓名/ID混用。
- **与其他部门的接口**：与生产车间的设备编号、设备位置和责任人信息核对；与模具维修的设备适配和维修记录衔接；与人事的员工ID/部门信息核对；如需采购或财务凭证，再与运营/财务既有记录衔接。
- **暂不能确认的字段/权限**：资产范围是否包括生产设备、模具、检具和低值易耗品；资产编号的生成和维护人；盘点频率、盘点人和差异批准人；保养记录是否另有现行记录；报废、调拨、借用的批准权限；责任人字段应填员工ID、姓名还是岗位；资产资料位置的访问权限。

## 五、跨模板的最小统一项（建议优先确认，不视为已实施）

1. **编号关联**：优先统一订单号、工单号、产品编码、材料编码/批次、模具编号、设备编号、异常编号、检验记录编号、员工ID、岗位ID的格式和来源；没有确认的编号不强行改写。
2. **状态字段**：先建立一页字段取值说明或在原工作表表头旁加注释，避免各表自行使用“完成、关闭、合格、已放行”等近义词；具体取值需由对应部门确认。
3. **责任与确认分开**：保留“记录人/执行人”和“确认人/批准人”两类角色，不默认两者相同；不据此推定审批权限。
4. **证据可追溯**：对照片、图纸、检验记录、培训材料等优先填写“证据编号/位置”，不要求在模板内重复粘贴文件内容。
5. **版本控制**：产品、图纸、材料、模具和模板本身均保留版本/生效日期概念；未确认的版本批准人和受控位置列为待确认。
6. **权限边界**：本清单只指出需要确认的字段和权限，不将“责任人ID”“确认人ID”“批准人”直接解释为正式授权矩阵。

## 六、检查结论

- 已检查上述 6 个现有 `.xlsx` 模板的工作表名称、主要字段和示例/空白行结构。
- 当前适合采取“原模板内小幅补字段、补取值说明、补关联编号”的方式；没有提出新建体系目录或平行模板。
- 本清单中的“最小必要补充”均为建议项，实施前应由对应部门确认字段口径、维护责任、批准/关闭权限和受限信息范围。
