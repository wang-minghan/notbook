# 会议流程与跨部门协同标准模板

> **文件定位**：本页是可直接复制使用的会议与协同模板，属于“拟建立机制”。它不证明公司已经按此执行，也不替代正式组织架构、授权矩阵、RACI或异常升级文件。
>
> **状态标记**：
> - **现行事实**：已由现有资料明确的事实或基线。
> - **拟建立机制**：本页建议采用的流程、字段和规则，待正式批准后实施。
> - **待确认事项**：角色姓名、会议频次、阈值、时限和授权边界等，必须由公司确认。

## 1. 通用执行规则

### 1.1 会议的最小闭环

每次会议必须留下六类信息：**输入 → 事实与问题 → 决策 → 责任人 → 期限 → 关闭证据**。没有责任人、期限或可验证证据的“安排”不得标记为已完成。

### 1.2 会议记录通用页眉

| 字段 | 填写内容 |
|---|---|
| 会议类型/编号 | 日班前、现场异常、周生产质量、月度经营、专项改善/客诉；编号：YYYYMMDD-类型-序号 |
| 日期、时段、地点/线上链接 |  |
| 主持人 | 角色名；实际姓名待确认 |
| 记录人 | 角色名；实际姓名待确认 |
| 会议状态 | 计划中 / 进行中 / 待决策 / 行动中 / 待验证 / 已关闭 |
| 适用状态 | 本模板默认“拟建立机制”，不得填成“已实施”除非有正式批准和执行记录 |
| 关联事项 | 订单、工单、异常编号、客诉编号、改善项目编号 |

### 1.3 行动项字段（所有模板通用）

| 编号 | 问题/目标 | 动作与交付物 | R（执行） | A（最终负责/批准） | C（协商） | I（知会） | 截止时间 | 验收标准 | 关闭证据 | 状态 |
|---|---|---|---|---|---|---|---|---|---|---|
| A-01 |  |  |  |  |  |  |  |  |  | 未开始 |

规则：一项行动只能有一个 **A**；RACI角色若尚未授权，标注“待确认”。“参加会议”不等于承担R或A。

### 1.5 50人规模的使用方式（单表优先）

本模板按约50人规模设计：不要求另设专职会议机构，也不要求每类会议单独建复杂台账。优先使用**一张会议/协同记录表**，每次只保留必要事项；同一人兼任多个角色时，仍须把R与A写清，不能因兼岗省略复核。

| 会议 | 建议频次 | 单表必填输入 | 当次必须形成的输出 | 默认牵头角色（待确认） |
|---|---|---|---|---|
| 日班前/现场异常 | 每班前；异常随时 | 当班计划、未结项、异常事实/批次/影响 | 当班安排、隔离/遏制、升级决定 | 班组长/生产现场负责人 |
| 周生产质量 | 每周 | 产出交付、质量数据、异常和逾期项 | 重点问题、唯一A、期限、验证方式 | 生产负责人或营运负责人 |
| 月度经营 | 每月 | 经营结果、客户/交付、资源和重大风险 | 公司级取舍、资源决定、决策台账 | 总经理/公司负责人 |
| 专项改善/客诉 | 按需 | 客诉/异常事实、范围、遏制、客户要求 | 根因、纠正措施、客户回复、关闭证据 | 品质负责人/项目负责人 |

若没有专门记录人，由主持人指定一人兼任；若事项只有一个部门，也必须保留输入、A、期限和证据四个最小字段。


## 2. 模板A：日班前会 / 现场异常快反会

> 适用：每日开班前的计划与风险对齐；或发生现场异常后，快速完成事实确认、遏制和升级。两者可共用一张记录，但异常事项不得被日常事项淹没。

### 2.1 输入

- 当班生产计划：订单、产品/料号、批次、数量、交期、设备/模具、人员与班次。
- 上一班未关闭行动项、交接记录和未决风险。
- 质量/设备/安全/环保现场异常：时间、地点、批次、现象、数量、照片/样品、初步影响。
- 物料、图纸、工艺参数、检验标准的当前版本；版本不明时标记“待确认”。
- 当日需跨部门交接的事项和资源约束。

### 2.2 参加角色

- 主持：生产现场负责人/班组长（**待确认**）。
- 必选：生产/冲压车间、制程巡检/品质、工程技术/模具维修（按事项参加）。
- 按需：采购/仓储、营运/���划、设备、安全环保、业务/客户接口（均**待确认**）。
- 记录：指定文控/会议记录人（**待确认**）。

### 2.3 会议步骤

1. **点名与安全确认**：确认人员、设备状态、特殊作业和现场安全风险。
2. **计划对齐**：逐项确认当班目标、关键质量点、物料/模具/设备准备情况。
3. **遗留项复盘**：只看逾期、临期和无证据关闭的事项。
4. **异常快报**：按“事实—影响—临时措施—需要决策”陈述，不在现场凭感觉定根因。
5. **遏制与交接**：明确停机/隔离/标识/复检/替代安排；接收方逐项确认输入完整。
6. **形成行动项和升级**：登记RACI、期限、证据；主持人复述所有决策。
7. **确认结束条件**：正常事项进入当班看板；异常进入异常编号和后续复盘。

### 2.4 决策规则

- 涉及人身安全、环保泄漏、火灾、重大设备风险：先现场保护和应急处置，再按异常升级规则上报；不得等待日会。
- 质量状态不明：默认隔离/暂停流转，未经品质授权不得放行；特殊放行权限待正式授权确认。
- 影响交期、客户承诺或跨部门资源的事项：由有授权的A决策；现场班组不得越权承诺。
- 信息不完整：不得以“先做再补资料”代替交接，除非有明确授权和风险控制。
- 争议事项不在会议上“投票通过”；记录分歧、指定A和升级对象。

### 2.5 行动项

至少包括：当班生产任务、物料/模具准备、首件/巡检安排、异常隔离与复检、责任部门交接、需升级事项。每项写明可交付物（如隔离清单、复检结果、参数确认单、维修报告），不得只写“跟进”“注意品质”。

### 2.6 关闭证据

- 班前事项：计划确认记录、物料/模具/设备点检结果、首件或开机确认记录。
- 现场异常：异常编号、隔离范围/标识照片、复检结果、放行或报废/返工批准、交接回执。
- 只有“口头已处理”而无上述证据，状态保持“待验证”。

### 2.7 升级规则

- 立即升级：安全/环保、人身伤害、火灾、重大设备风险、无法识别的批次影响、疑似已流出不合格品。
- 当班内升级：质量连续重复、良率明显下降、停机影响计划、物料/图纸版本冲突、责任部门未接收。
- 若超过本模板约定时限仍无A或无遏制措施，升级至营运/生产负责人和总经理（具体层级与时限**待确认**）。
- 升级记录至少包含：异常编号、事实、影响范围、已采取措施、请求决策、下一次更新时间。

## 3. 模板B：周生产质量协调会

> 适用：每周对生产、质量、设备、物料和交付风险进行趋势复盘，关闭跨部门行动项。不是把日会记录简单汇总。

### 3.1 输入

- 周计划与实际产出、达成率、交期风险。
- 不良率、返工/报废、首件/制程/出货检验数据，按产品/批次/工序分层。
- 本周异常清单、重复异常、逾期行动项、放行/让步记录。
- 设备/模具故障与维修、停机时间、备件风险。
- 物料到料、来料质量、供应商异常；客诉和退货趋势（如有）。
- 上周决策关闭证据及下周计划输入。

### 3.2 参加角色

- 主持：生产负责人或营运/计划负责人（**待确认**）。
- 必选：生产、品质、工程技术/模具维修、营运/计划。
- 按需：采购、仓储、业务/客户接口、设备、安全环保、财务（均**待确认**）。
- 记录：品质或运营数据负责人（**待确认**）。

### 3.3 会议步骤

1. 数据口径确认：周期、订单/批次范围、数据版本和缺失项。
2. 先看红线：安全环保、客户风险、质量放行、重大交期和重复异常。
3. 看趋势而非单点：目标—实际—差距—影响—主要原因假设。
4. 逐项复盘上周行动：证据不足不关闭，逾期事项重新定A和期限。
5. 跨部门专题：对高损失/高频/高风险事项做5Why、鱼骨或其他已批准方法分析。
6. 形成本周决策、资源需求、责任分工和验证计划。
7. 主持人确认升级事项和下周输入清单，记录人发布纪要。

### 3.4 决策规则

- 指标口径不一致时先冻结结论，指定数据责任人和校准期限，不以争论替代事实。
- 质量放行、客户承诺、重大资源和费用事项按授权矩阵执行；会议结论不得自动取得超授权批准。
- 根因未验证时只能批准临时遏制，不能宣称永久措施有效。
- 重复异常或跨两周未关闭的问题必须转为专项改善或升级管理评审。
- 每项决策必须写出“决定什么、谁批准、何时生效、如何验证”。

### 3.5 行动项

优先登记四类：质量损失降低、交期恢复、设备/模具可靠性、跨部门输入输出标准化。行动项必须有量化目标或明确验收标准，例如“连续三批不良率低于X（X待确认）并有检验记录”，不能只写“持续改善”。

### 3.6 关闭证据

- 周报/看板数据及口径说明。
- 异常分析、临时措施和永久措施记录。
- 连续批次/周期的验证数据、首件/巡检/出货结果。
- 交接双方确认记录、修订后的作业文件/参数/检验标准（如适用）。
- 由A或被授权验证人签字/电子确认；会议记录人不能单独代替业务验证。

### 3.7 升级规则

- 质量或交期风险达到既定红线、客户风险增加、重大异常重复发生时，立即进入异常升级流程。
- 同一行动项逾期一次：周会重新定责；逾期两次、影响客户/交期或跨部门争议未解决：升级至部门负责人/总经理（层级待确认）。
- 需要改变资源、授权、客户承诺或制度时，提交月度经营会或正式审批，不在周会越权决定。

## 4. 模板C：月度经营会

> 适用：月度经营结果、资源与重大风险决策；聚焦公司级取舍，不替代日常生产协调。

### 4.1 输入

- 月度经营指标：订单、收入/回款、毛利或成本、产能、交付、质量、客诉、现金与重大费用（数据可得性和口径待确认）。
- 上月决策及关闭证据；逾期和重复问题。
- 未来1—3个月订单、客户承诺、产能/人力/设备/模具/物料约束。
- 重大风险登记、异常升级记录、供应商/客户重大事项。
- 需要经营层决策的选项、成本、风险、期限和不决策后果。

### 4.2 参加角色

- 主持/最终经营裁决：总经理或公司负责人（**待确认**）。
- 必选：营运/计划、生产、品质、业务、财务。
- 按议题参加：采购、仓储、工程技术/模具、行政/人事、安全环保（均**待确认**）。
- 记录与追踪：经营管理/文控角色（**待确认**）。

### 4.3 会议步骤

1. 确认经营数据、口径、缺失项和本次需要决策的议题。
2. 先审经营红线：安全环保、客户交付、质量、现金和合规风险。
3. 对比目标与实际，说明差距、影响和趋势；区分事实、判断、假设。
4. 对重大事项提供至少一个可行选项及其资源、成本、风险和截止时间。
5. 按授权矩阵作出决策；超授权或涉及正式制度变更的事项形成待批准项。
6. 确定公司级行动项、唯一A、里程碑和证据要求。
7. 复述决策及未决事项，发布纪要、决策台账和下月输入要求。

### 4.4 决策规则

- 公司级事项只有被授权的经营负责人可作最终A；其他角色提供R/C/I，不得通过会议席位自然取得批准权。
- 数据不完整时可以作“有条件决策”，但必须写明前置条件、补充数据责任人和复议日期。
- 经营会不追究未经核实的个人归因；先确定事实、系统原因、责任A和控制措施。
- 重大资源冲突按公司目标、客户风险、质量与安全优先级排序；无法裁决则进入更高授权层级。
- 任何对外承诺、费用、人员、价格或质量放行须符合正式授权文件；未确认部分标“待确认”。

### 4.5 行动项

形成经营决策台账，至少包括：决策编号、背景事实、选项、最终决定、A/R/C/I、预算/资源边界、里程碑、截止时间、验证人、关闭证据和复议条件。

### 4.6 关闭证据

- 决策批准记录和授权依据。
- 预算/资源配置、订单/客户沟通、计划变更或制度修订记录。
- 结果数据与目标对比，必要时附财务、质量、交付和客户证据。
- A确认结果，且风险登记、异常台账或行动项台账已同步更新。

### 4.7 升级规则

- 触及安全、环保、重大质量、重大客户或现金风险红线：不等待月会，立即按异常升级规则处理。
- 经营决策逾期、资源无法落实或结果偏离承诺：由记录人/事项A在发现后升级至主持人；重大事项由总经理/公司负责人裁决。
- 任何会议无法合法/授权决策的事项，标为“待批准”，不得写成“已决定”。

## 5. 模板D：专项改善 / 客诉闭环会

> 适用：重大或重复异常、客户投诉、退货、审核不符合、跨部门改善项目。客诉事项必须兼顾客户沟通、遏制、根因、纠正预防和效果验证。

### 5.1 输入

- 专项/客诉编号、客户、产品/料号、订单/批次、数量、发现时间、现象和影响。
- 客户要求、图纸/规范/样品、检验记录、生产/设备/模具/物料履历、流出范围。
- 已采取的遏制措施、库存/在制/已交付品状态、客户沟通记录。
- 可能原因、已验证事实、未知项；区分事实与假设。
- 目标、期限、资源需求、适用RACI和异常升级级别。

### 5.2 参加角色

- 主持/项目A：品质部负责人或被指定的改善项目负责人（**待确认**）。
- 必选：品质、生产、工程技术/模具维修、营运/业务客户接口。
- 按需：采购/供应商、仓储、设备、财务、总经理/公司负责人、客户代表（均**待确认**）。
- 记录/证据管理员：品质或文控角色（**待确认**）。

### 5.3 会议步骤

1. **定义问题**：确认客户/内部要求、缺陷定义、范围、严重度和���前状态。
2. **立即遏制**：隔离、标识、暂停出货/生产、追溯筛选和客户临时沟通；明确批准边界。
3. **确认流出与影响**：查库存、在制、已交付、相关批次/机台/模具/材料和相邻产品。
4. **根因分析**：用数据和现场证据验证发生原因、流出原因和系统原因；未经验证的仅列假设。
5. **制定措施**：分别定义临时纠正、永久纠正、预防/系统控制；每项指定唯一A和验证方法。
6. **评审资源与时限**：确认客户回复、样品/报告、工程变更、培训、文件更新等输入输出。
7. **效果验证**：按约定批次/周期验证，确认无复发和控制点有效；无证据则保持开放。
8. **关闭与复盘**：A批准关闭，更新客诉/异常/风险台账，必要时将经验纳入标准和培训。

### 5.4 决策规则

- 客诉事实、责任归因和对外承诺分开记录；不能因客户压力跳过遏制和验证。
- 质量放行/让步、客户回复、工程变更和费用承担按授权矩阵执行；角色未确认时不得擅自承诺。
- 根因不明可先作风险控制，但必须列出补证据计划和截止时间。
- 永久措施必须能改变过程控制或检测能力；“提醒员工”“加强注意”不能单独作为有效纠正措施。
- 一项措施只有一个A；涉及多个部门时由项目A协调，不能由“大家负责”。

### 5.5 行动项

至少拆成：客户临时回复、库存/在制/已交付品处置、筛选与复检、根因验证、永久纠正、文件/参数/模具/检验变更、培训与上岗确认、效果验证、客户关闭确认。每项写明输入、输出、责任、期限和验收标准。

### 5.6 关闭证据

- 客诉/异常报告、遏制范围和追溯清单。
- 根因验证数据、照片/样品/检验记录及分析结论。
- 纠正措施实施证据：变更记录、参数/图纸/检验标准版本、维修或改造报告、培训记录。
- 效果验证数据：连续批次/周期、客户确认或内部等效验证。
- 客诉关闭批准、客户往来记录（如适用）、风险/行动台账更新。

### 5.7 升级规则

- 涉及人身安全、法规环保、重大客户影响、批量流出、无法遏制或疑似系统性问题：立即升级至品质负责人、总经理/公司负责人，并按安全应急和异常升级路径处理。
- 客户回复、遏制或永久措施逾期：在截止时限前预警；到期无输出即升级项目A和经营负责人。
- 同类问题重复发生、效果验证失败、跨部门无法取得输入或措施需要重大资源/授权：升级月度经营会或更高授权层级。

## 6. 与现有治理基线的接口

### 6.1 与治理PPT第28页的接口

现行治理基线把第28页定义为“安全、环保与应急”，流程语义为：**发现 → 现场处置 → 上报 → 调查 → 整改 → 验证**。本页的接口如下：

| PPT第28页环节 | 本模板承接位置 | 输出/接口要求 |
|---|---|---|
| 发现 | 日班前/现场异常、周会异常输入 | 异常编号、时间地点、事实、照片/样品、初步影响 |
| 现场处置 | 现场异常步骤5、专项改善步骤2 | 人员保护、停机/隔离/标识、环保控制；不得等待普通会议 |
| 上报 | 各模板升级规则 | 按严重度和授权路径通知；角色、阈值、响应时间仍待确认 |
| 调查 | 周会专题、专项改善步骤4 | 证据链、影响范围、发生/流出/系统原因；事实与假设分开 |
| 整改 | 行动项、专项改善步骤5 | 唯一A、RACI、期限、验收标准；需要授权的变更走正式审批 |
| 验证 | 关闭证据 | 复检、连续批次/周期数据、客户确认或内部验证；A批准关闭 |

说明：本页**没有把第28页的流程设计宣称为已实施**，也没有自行补写安全/环保等级、响应时限、通知名单或停产权限；这些属于待确认事项。

### 6.2 与RACI的接口

- 依据现有治理基线：一项事项只能有一个最终负责/批准主体（A）；RACI用于区分R、A、C、I，不能用参加会议代替责任。
- 会议纪要中的A必须能在正式RACI/授权矩阵中找到；找不到时标“待确认”，不得自行推定。
- 当前可作为基线校验的事项包括：重大生产异常处置（A基线为总经理，具体角色/授权仍需确认）、首件/制程检验及异常放行（A基线为品质部）、客诉关闭（A基线为品质部）。这些是现有资料中的责任基线，不等同于本模板已落地。
- 采购验收、仓储收货、来料质量检验、付款审批等必须拆成不同事项，不得在会议行动项中合并成“采购负责”。
- 当会议需要新增事项时，先登记“事项—输出—R—A—C—I—授权依据”，再回填正式RACI矩阵；RACI冲突时暂停越权决策并升级。

### 6.3 与异常升级机制的接口

- 会议是异常信息的**汇总、决策和追踪场景**，不是替代异常升级通道。安全、环保、重大质量、客户流出等事项应即时升级。
- 升级记录必须携带：异常编号、等级/判定依据（若等级尚待确认则明确标注）、事实、影响范围、已采取遏制、请求决策、责任A、下一次更新时间和关闭证据。
- 现场发现先处置和隔离，再上报、调查、整改、验证；不得因等待周会/月会而延误控制。
- 逾期、重复、跨部门不接收、无授权或验证失败均是二次升级触发器。
- 具体一级/二级/三级定义、阈值、响应时间、通知对象和最终关闭权限目前属于**待确认事项**，须由公司负责人依据正式授权文件确认后写入异常升级规则。

### 6.4 与跨部门交接标准的接口

每个会议行动项同时视为一次可追踪交接：发起方提供完整输入，接收方确认接收或退回差异；输出必须有验收标准和关闭证据。对图纸、材料、批次、版本、数量、期限不清的事项，状态保持“待补充”，不得默认为已完成交接。
