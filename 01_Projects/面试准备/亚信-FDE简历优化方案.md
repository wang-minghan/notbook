# 亚信经历｜FDE/AI应用交付简历优化方案

> 目标不是把经历吹成“纯FDE”，而是把真实经历重写成 **AI Forward Deployed Engineer / AI应用交付工程师 / Applied AI Engineer** 能识别的语言。没有证据的客户数量、部署规模、准确率和上线数据不能补写。

## 一、结论：你的最佳定位

### 主定位
**AI应用交付工程师 / Forward Deployed AI Engineer**

### 次定位
- Applied AI Engineer
- LLM/RAG/Agent Engineer
- 大模型解决方案工程师
- AI技术交付/售前技术支持工程师

### 不建议直接定位
- 纯算法研究员：现有材料更强的是应用落地、系统编排和业务约束，不是论文/基础模型研究。
- 纯后端工程师：会浪费 RAG、知识图谱、Agent 和大模型部署这组差异化能力。
- 直接写“高级FDE”：当前材料还缺少明确的客户现场、生产环境、部署规模和持续运维证据，先用“AI应用交付/FDE方向”更稳。

## 二、市场信号与关键词策略

近期公开岗位和FDE简历指南反复出现六类筛选信号：

1. **生产交付**：production system、deployment、上线、稳定性、监控、迭代维护。
2. **客户/业务协同**：customer discovery、stakeholder management、需求澄清、技术方案、跨团队交付。
3. **复杂数据处理**：企业知识库、脏数据、权限、数据接入、数据治理、结构化与非结构化数据。
4. **端到端 ownership**：从需求分析、方案设计、开发验证到部署和效果复盘。
5. **AI应用深度**：LLM、RAG、hybrid retrieval、reranking、knowledge graph、Agent、tool calling、evals、LoRA、推理部署。
6. **业务结果**：响应时间、人工干预、交付周期、准确率、召回率、客户采用率、成本。

BOSS公开职位中常见的中文词包括：**AI方案设计、Agent开发、系统集成、效果调优、私有化部署、客户需求分析、业务流程梳理、交付体系、RAG、推理优化、信创与数据安全**。这些词应该出现在简历的“求职方向/概述/技能/经历”中，但必须和真实做过的工作绑定，不能机械堆词。

## 三、现有亚信经历审计

### 已有、可以直接使用的事实

- 多 Agent 大模型推理增强系统设计。
- 混合检索：BM25 + BGE + RRF + Cross Encoder。
- Neo4j 本体知识建模与关系约束推理。
- Qwen + LoRA 领域微调与 vLLM 推理部署。
- 语义指令映射，把业务规则转为可组合指令单元。
- 覆盖售前、售后、数据中台和产品设计等业务场景。
- 人工干预减少70%以上，响应时间降低20%。**这两个数据必须补充统计口径和对比基线。**

### 目前最影响通过率的缺口

- 没有写清楚你对接的是内部团队、客户还是客户项目；不能把“推动客户交付”直接写成“长期驻场客户交付”，除非确实如此。
- 没有写清楚系统是否生产上线、部署环境、调用规模、并发、SLA或维护周期。
- 没有给出RAG/Agent效果指标，例如Recall@K、NDCG、命中率、人工接管率、任务成功率、幻觉率或响应P95。
- “负责多Agent协同工作流、状态管理和数据库设计”偏职责描述，必须改成系统边界、关键决策和结果。
- 目前技术栈很强，但业务结果不够靠前；FDE岗位不会因为技术名词多就自动认为你能交付。

## 四、推荐简历顶部定位

### 中文版
**AI应用交付工程师 / 大模型应用工程师**

聚焦企业级大模型应用落地，具备从业务场景梳理、知识建模、RAG检索、Agent工作流设计，到模型微调、推理部署和效果评估的端到端经验。擅长将企业规则、知识和动作转化为可约束、可追踪、可交付的AI系统，能够联动产品、数据、研发和业务团队推进方案落地。

### 英文关键词版
**Applied AI / Forward Deployed AI Engineer | LLM Applications | RAG | Agentic Workflows | Knowledge Graph | LoRA | vLLM**

## 五、亚信经历优化稿（证据版）

> 公司名称、职务、起止时间按正式简历原始信息补齐。下面只优化表达，不替你虚构职位级别或项目数据。

### 亚信科技（中国）有限公司｜高级人工智能工程师
**时间：2025年8月–2026年8月｜方向：Enterprise AI / RAG / Agent / Knowledge Graph**

- **主导企业级RAG知识库增强问答系统的核心架构设计**，将BM25关键词检索、BGE向量检索、RRF融合与Cross-Encoder重排组合为混合检索链路，针对企业术语、长文档和多轮上下文场景提升召回与排序稳定性。
- **面向运营商企业业务部门交付AI应用数据底座**，在客户内网完成私有化部署，处理每日更新的单表约53万条记录，覆盖客户画像、产品与渠道等核心业务维度；负责数据清洗、字段映射、知识图谱建模与检索接入，支撑客户分析、产品/渠道问答和Agent任务编排，项目已正式交付。
- **针对纯RAG场景中答案有依据但推理链不完整、目标易漂移的问题，设计基于Neo4j本体的知识建模与约束推理层**，将企业本体作为语义数据目录，显式管理实体、关系、业务规则、数据血缘与可执行动作，减少大模型找不到数据、找错数据及遗漏关联推理的问题。
- **设计结构化数据、向量数据与图谱数据三类存储协同架构**，分别承载业务事实、语义检索和关系/血缘推理，通过检索、实体校验、关系约束和推理路径裁剪形成可追踪的多步推理链。
- **负责多Agent协同工作流、状态管理和数据库设计**，将复杂业务任务拆分为可编排的Agent节点与工具调用流程，围绕任务状态、上下文传递、异常处理和结果回写构建可复用的应用层能力。
- **完成Qwen模型LoRA领域微调与vLLM推理部署**，围绕业务指令、术语理解和任务执行场景设计训练/验证流程，结合bad case分析与离线评估持续迭代模型和检索策略。
- **将业务规则转化为语义指令映射与可组合动作单元**，连接企业知识、规则和Agent执行链路，使系统从“检索信息”扩展到“按约束推理并执行任务”。
- **在客户前线协助完成企业本体搭建与平台使用交付**，将一次性生成式问答改造成可视化、可分步检查的AI推理流程，使业务人员能够查看中间依据、推理路径与执行步骤，提升结果可解释性、交付可信度和问题定位效率。
- **联动产品、数据、研发及业务团队推进方案验证与场景落地**，覆盖售前支持、售后服务、数据中台和产品设计等场景；现有材料记录人工干预减少**70%+**、响应时间降低**20%**，需在最终简历中补充统计周期、基线、样本量和归因口径。

### 核心业务问题与解决方案

客户在使用大模型进行业务推理时，纯RAG通常只能返回若干“有依据的理由”，但不一定能覆盖完整的数据血缘、业务关系和专家判断链路，容易出现目标偏移、遗漏关键关联和交付漂移。

本项目通过“结构化数据库 + 向量数据库 + 图数据库”三类存储协同，将企业事实、语义相似性和实体关系/数据血缘分别建模；再利用本体约束、路径裁剪和Agent工作流，把一次性生成转化为可分步骤执行、可视化检查、可回溯验证的推理过程。以“客户满意度下降原因分析”为例，系统不只检索可能原因，还需要沿客户画像、产品、渠道及相关业务关系展开证据链，帮助专家判断结论是否足以支撑交付。

## 八、必须补齐的硬证据清单

1. 亚信正式职位：高级人工智能工程师；任职时间：2025年8月–2026年8月；外部企业客户包括中国联通、中国移动；总工作年限2年；教育背景见个人资料页；仍需补充所在团队、具体项目和协作方式。
2. 主要服务对象：中国联通、中国移动等外部企业客户；仍需补充客户数量/项目数量、是否驻场或远程协作。
3. 系统状态：已正式交付，在客户内网完成私有化部署；不声称最终生产使用方式，除非后续获得客户侧信息。
4. **数据规模与交付范围**：每日更新的单表约53万条记录，包含客户画像、产品和渠道等核心业务维度；交付给客户业务部门；最终使用部门、用户数量、调用量和内部使用方式未知，不在简历中编造。
5. 检索/问答指标：Recall@K、NDCG、准确率、任务成功率、人工接管率、幻觉率或响应P95。
6. “人工干预减少70%+”和“响应时间降低20%”的原始统计表或至少统计口径。
7. 你本人负责的边界：独立完成、主导设计、与谁协作、哪些模块由别人负责。
8. 部署细节：GPU/CPU、Docker/Kubernetes、云上或私有化、监控、日志、权限和安全要求。
9. 客户/业务反馈：验收、复用、续用、交付周期缩短、成本降低等可验证结果。

## 九、执行顺序

- **第1步：证据回填**。先补齐上面的9类事实，不急着继续润色。
- **第2步：做三版简历**。FDE版、AI应用工程版、大模型算法版；不要一份简历投所有岗位。
- **第3步：做BOSS关键词映射**。每个目标JD提取20-30个核心词，保留真实匹配词，按岗位替换标题和前3条经历。
- **第4步：做项目作品证明**。至少准备一张架构图、一页评估结果、一段脱敏Demo或代码/文档说明，否则FDE定位会停留在简历包装层面。
- **第5步：准备面试深挖包**。能讲清需求、架构、取舍、失败案例、指标口径、上线问题和客户/业务沟通。

## 十、当前判断

你的经历**具备包装成FDE/AI应用交付方向的基础**，当前已经有客户、私有化部署、正式交付、53万条每日更新数据和前线本体搭建等关键证据；下一步重点是补上 **客户/业务对象、端到端负责边界、指标口径和部署约束** 这四组证据。
