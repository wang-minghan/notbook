# 鑫犇治理PPT视觉重绘总规划 V4.0

> 本文件是 20—25 页及 32 页重绘的总规划。它负责把内容主题、图示语法、视觉锚点和验收标准统一起来；不是演讲者备注，也不是替代 `design_spec.md` / `spec_lock.md` 的技术锁定文件。
>
> 当前状态：方案已完成，等待逐页执行。未确认的岗位、权限、时限和保存期限不得写成现行事实。

## 一、审查结论

### 当前真实问题

1. 第 20—25 页和第 32 页都保留了“六个横向步骤卡片”的共同骨架。
2. 每页虽然引用了不同的 SVG，但这些 SVG 只是通用生命周期、PDCA、订单变更或采购付款图，不能充分表达当前页的主题。
3. 当前页面的主图大多是装饰性引用，而不是责任、判断、记录和异常关系的载体。
4. 第 32 页标题是 RACI 示例，但当前视觉仍接近流程链，缺少真正的事项×部门交叉矩阵。
5. 当前项目已有 `design_spec.md`、`spec_lock.md`、`flow_design_baseline_v2.md`、`restructure_spec_v2.md`、`responsibility_baseline_v2.md`、`confirmation_list_v2.md` 和 `diagram_review_v3.md`，但没有一个文件统领本轮 20—25、32 页的视觉重绘执行顺序。

## 二、整体视觉策略

### 统一原则

- 不再把所有页做成横向步骤链。
- 每一页只使用与主题匹配的图示语法。
- 保留浅灰白背景、深蓝灰文字和现有蓝/青绿/橙/紫/红/黄语义色。
- 配图只承担语义锚点，不用无关图片填空。
- 继续使用可编辑 SVG 原语，不把整页做成一张扁平图片。
- 适合使用制造现场、文件、档案、权限和会议等语义图标；如果没有真实照片，优先使用结构化示意图，不强行生成“假现场照片”。

### 图例

- 蓝色：输入、主结构、责任接口
- 青绿色：协同、记录、验证、关闭
- 橙色：审批、授权、管理决策
- 紫色：专业判断、能力、技术或品质
- 红色：异常、拒绝、隔离、升级
- 黄色：风险、待确认、条件闸口
- 实线：正常主路径
- 虚线：异常、升级、信息同步或退回

## 三、逐页重绘方案

### 第 20 页｜跨部门交接标准

- 页面角色：交接控制页，不是普通生命周期。
- 主图语法：**双端交接桥 + 输入/输出闸口**。
- 左侧：交出方的输入包，包含版本、数量、状态、责任人和期限。
- 中间：完整性闸口，六项检查以清单/勾选结构呈现。
- 右侧：接收方的验收包，包含接收确认、差异记录和异常升级。
- 下方：异常回路，缺项时退回交出方，不得直接进入下一部门。
- 视觉锚点：文件包、交接箭头、验收印章或清单图标。
- 关键验收：必须能看出“谁交给谁、交什么、如何验收、缺项退回谁”。

### 第 21 页｜文件编制与版本控制

- 页面角色：受控文件生命周期。
- 主图语法：**环形生命周期 + 版本分叉**。
- 主环：起草 → 评审 → 批准 → 发布培训 → 执行记录 → 复审/修订。
- 版本分叉：修订后生成新版本；旧版进入隔离/作废区，不回到主流程。
- 右侧证据栏：审批记录、版本清单、培训记录、旧版回收记录。
- 视觉锚点：叠放文件、版本标签 V1/V2/V3、旧版回收箱。
- 关键验收：必须明确“新版本发布”和“旧版本隔离”是两个不同动作。

### 第 22 页｜记录与档案生命周期

- 页面角色：记录从形成到处置的可追溯链。
- 主图语法：**时间轴 + 档案分层漏斗**。
- 左侧时间轴：形成 → 审核 → 编码归档 → 权限保存 → 检索借阅 → 到期处置。
- 中间分层：普通记录、受限记录、关键经营/质量记录；不同层级对应不同访问控制。
- 右侧：检索和处置分支，显示借阅留痕、到期审批、销毁/保留决定。
- 视觉锚点：档案盒、索引、锁、检索、销毁审批。
- 关键验收：不能只画“归档”，必须显示权限、借阅留痕和到期处置。

### 第 23 页｜人员能力与岗位授权

- 页面角色：能力到授权的闸门。
- 主图语法：**能力阶梯 + 授权生命周期**。
- 阶梯：培训 → 能力确认 → 上岗授权；每一级有记录证据。
- 授权生命周期：维护 → 复训/调岗 → 暂停/替代 → 离岗回收。
- 红色/黄色分支：能力未确认不得授权；调岗或离岗必须触发权限回收。
- 视觉锚点：能力徽章、授权钥匙、替代人、回收锁。
- 关键验收：必须看出“培训不等于授权”，授权前有能力闸门，离岗有回收。

### 第 24 页｜客户资料与信息权限

- 页面角色：信息访问控制。
- 主图语法：**资料分级漏斗 + 角色权限矩阵 + 回收分支**。
- 左侧：客户图纸、报价、工艺、质量、人事资料按敏感度分级。
- 中部：申请 → 审批 → 最小权限使用 → 访问留痕。
- 右侧：离岗/岗位变化/异常泄露触发回收和上报。
- 底部：按角色显示“可见/不可见/需审批”，不写死未确认岗位权限。
- 视觉锚点：文件、锁、钥匙、访问日志和回收箭头。
- 关键验收：必须区别资料分级、权限批准、使用留痕和回收，不画成普通人员生命周期。

### 第 25 页｜经营会议与管理闭环

- 页面角色：会议产出管理闭环。
- 主图语法：**会议中心辐射 + 事项闭环**。
- 中心：经营会议/管理评审，不把“开会”本身作为终点。
- 四个输入：交付、质量、采购/供应、现金/能力/整改等数据和风险。
- 四个输出：决定、责任人、期限、验收标准。
- 外圈回路：跟踪 → 到期验证 → 完成归档；未完成进入红色升级分支。
- 视觉锚点：会议桌、决议文件、责任卡、日历期限、验证勾选。
- 关键验收：必须能看出会议之后产生责任、期限和关闭证据。

### 第 32 页｜部门协同 RACI 示例

- 页面角色：责任校准示例，不是流程图。
- 主图语法：**真正的 RACI 交叉矩阵**。
- 行：订单评审、技术变更、采购验收、质量放行、客诉关闭、付款批准。
- 列：营运部、生产、品质、技术/工程、采购/仓储、财务、管理层等责任接口。
- 单元格：R/A/C/I 以颜色和字母标识；每行只突出一个 A，若待确认则标注“待确认”。
- 右侧小结：三条规则——一项事项一个 A、R 负责执行、C/I 不能替代授权。
- 视觉锚点：矩阵、唯一 A 高亮、待确认标签、责任校准标记。
- 关键验收：不能继续使用采购付款 SVG；必须一眼看出这是交叉责任矩阵。

## 四、页面之间的节奏

- 20：交接桥，强调“交付完整性”。
- 21：文件环，强调“版本受控”。
- 22：档案时间轴，强调“记录可追溯”。
- 23：能力阶梯，强调“授权有门槛”。
- 24：权限漏斗，强调“访问可控制”。
- 25：会议闭环，强调“决定必须关闭”。
- 32：责任矩阵，强调“谁负责、谁批准、谁参与、谁知会”。

这组页面不再连续使用相同的横向卡片结构，形成“交接—文件—记录—人员—权限—会议—矩阵”的视觉节奏。

## 五、执行顺序

1. 先重绘第 20 页，建立交接桥和异常退回的视觉语言。
2. 重绘第 21、22 页，形成文件与记录的两个不同生命周期语法。
3. 重绘第 23、24 页，形成能力���权与信息权限的两个不同控制语法。
4. 重绘第 25 页，建立会议到关闭证据的管理闭环。
5. 最后重绘第 32 页 RACI 矩阵，并与第 10、11 页检查颜色和术语一致性。
6. 每页完成后执行人工结构检查，再运行 `svg_quality_checker.py`。
7. 七页完成后执行 `workflow_gate.py`、`finalize_svg.py`、`svg_to_pptx.py`，并回读 PPTX 页数、备注和关键文字。

## 六、禁止事项

- 不使用同一张通用流程 SVG 作为 20—25、32 页的主图。
- 不把文件生命周期、档案生命周期、人员授权和信息权限画成同一个环。
- 不把 RACI 页画成步骤流程。
- 不把未经公司确认的岗位、权限、时限和保存年限写成既成事实。
- 不因为增加配图而遮挡责任路径、判断节点或记录证据。
