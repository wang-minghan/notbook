# 鑫犇电子跨部门流程图设计基线 V2.0

> 目标：把“步骤列表”改成可以检查责任、审批、异常和记录的管理流程图。以下为正式绘图前的内容基线；实际责任人、权限金额和时限仍以公司确认结果为准。

## 统一图例

- 蓝色泳道：客户/营运部/业务
- 青绿色泳道：生产/仓储/采购等执行接口
- 紫色泳道：技术/工程/品质等专业判断
- 橙色节点：审批或决策
- 红色节点：异常、拒绝、升级或隔离
- 绿色节点：记录、验证、关闭
- 实线箭头：正常流程
- 虚线箭头：信息同步或结果知会

每张图必须显示：输入、责任岗位/部门、判断节点、输出、记录、异常回路、升级对象。

## 流程一：订单到交付总流程

### 目的

把客户承诺变成跨部门共同确认的交付计划，避免营运部单独承诺、生产被动接单或品质事后补救。

### 泳道

客户/业务｜营运部｜生产｜技术/品质｜采购/仓储｜授权管理层

### 主流程

1. 客户需求/订单进入营运部；记录：客户需求或订单原始资料。
2. 营运部检查信息完整性；不完整时退回补充并留痕。
3. 发起订单评审；并行征求产能、技术/质量、材料/交期意见。
4. 各责任部门提交确认结果和风险。
5. 判断：是否满足产品、质量、数量、交期和资源要求？
6. 不满足：形成风险和条件清单，升级授权管理层或与客户协商。
7. 满足：形成订单评审结论和批准的交付承诺。
8. 营运部发布受控订单/交付信息；生产生成任务，采购/仓储准备资源。
9. 执行、质量确认、出货和客户回传。
10. 形成订单履历并关闭。

### 关键控制点

- 订单承诺必须建立在部门确认基础上；
- 客户图纸/版本必须受控；
- 变更不得只通过口头信息传递；
- 交付风险必须有责任人、期限和升级对象。

## 流程二：客户/合同/订单/图纸变更

### 泳道

客户/营运部｜技术/品质｜生产｜采购/仓储｜授权管理层

### 主流程

客户提出变更 → 营运部登记变更申请 → 判断是否影响图纸、材料、工艺、质量、交期或价格 → 相关部门评估 → 汇总影响和可行方案 → 授权人批准或拒绝 → 更新受控版本/订单/任务/采购信息 → 旧版隔离回收 → 客户确认与内部发布 → 执行后验证 → 变更关闭。

### 必须设置的判断节点

- 是否已投料或已生产？
- 是否涉及旧版库存或在制品？
- 是否需要客户书面确认？
- 是否影响价格和交期？
- 是否需要重新首件或质量验证？

### 记录

变更申请单、影响评估、批准记录、版本清单、旧版回收记录、验证记录。

## 流程三：采购到付款

### 泳道

需求部门｜采购｜品质/技术｜仓储｜财务｜授权批准人

### 主流程

需求提出 → 需求和规格确认 → 供应商选择/评价 → 采购申请审批 → 采购订单 → 到货登记 → 品质/技术验收 → 判断合格？ → 合格入库/不合格隔离与处置 → 对账（三单或等效资料核对） → 财务付款审核 → 授权批准 → 付款记录 → 供应商绩效复盘。

### 控制原则

- 提出需求、批准采购、验收、入库、付款尽量分离；
- 供应商评价不能只看价格，应结合质量、交期和异常响应；
- 未完成验收或异常未处置，不应直接作为正常付款依据；
- 若公司人员有限而存在兼岗，必须通过复核、授权和���录补充控制。

### 记录

采购申请、比价/供应商评价、采购订单、到货登记、检验/验收记录、入库单、对账资料、付款审批、供应商绩效记录。

## 流程四：质量异常与放行

### 泳道

发现岗位/生产｜品质｜技术｜营运部｜授权管理层/客户

### 主流程

异常发现 → 标识和隔离 → 品质登记与初步分级 → 判断是否影响在制品、库存、交期或客户 → 专业调查和临时措施 → 判断是否可返工/让步/报废/继续生产 → 需要授权或客户批准时升级 → 形成处置批准 → 执行处置 → 效果验证 → 关闭并更新风险/标准。

### 不允许的路径

- 生产人员自行解除隔离；
- 未经授权用口头方式放行；
- 以交期压力替代质量判定；
- 只处理结果而没有原因和验证记录。

### 记录

异常单、不合格品隔离记录、临时措施、原因分析、处置批准、让步/客户确认、验证记录、关闭记录。

### 权限说明

品质是否拥有最终放行权、让步权限和客户沟通权限必须以正式授权矩阵确认；图中使用“品质专业判断”和“授权批准”两个概念，不预设未确认的组织事实。

## 流程五：模具/设备/关键资源状态

### 泳道

生产｜技术/工程｜品质｜采购/外协｜管理层

### 主流程

资源需求或异常提出 → 状态确认（可用/待维护/隔离/报废评估）→ 影响产能和质量评估 → 维修、调整、外协或替代方案 → 完成后状态确认 → 必要时首件/验证 → 恢复使用批准 → 履历更新 → 定期复盘。

### 治理层表达

本流程只规定状态、责任、批准和履历，不规定具体维修动作、加工参数或设备操作方法。

## 流程六：跨部门异常升级与关闭

### 统一模板

发现 → 登记 → 分级 → 临时控制 → 指定责任人 → 明确期限 → 原因分析 → 纠正措施 → 效果验证 → 管理层复核 → 关闭/再升级。

### 分级建议

- 一级：局部问题，不影响客户、交付或安全；部门内处理。
- 二级：可能影响批量、交期、质量或成本；部门负责人协调并限期升级。
- 三级：已影响客户、重大质量、安全、法规或经营目标；立即上报最高授权管理层。

等级、响应时限和升级岗位必须由鑫犇确认后固化。

## 流程七：会议与管理闭环

### 泳道

部门负责人｜总经理/经营管理层｜责任部门｜行政/文件管理

### 主流程

部门数据和风险输入 → 会议议题筛选 → 管理层决策 → 输出责任人、期限和验收标准 → 事项跟踪 → 到期验证 → 未完成则升级 → 完成关闭并归档 → 纳入指标和PDCA。

### 会议不可只记录

- 开了什么会；
- 谁参加了会；
- 讨论了什么。

必须记录：决定、责任人、期限、输出物、验证人和关闭证据。
