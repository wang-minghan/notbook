# 质量异常隔离与关闭：现状核对

> 本文只用于决策准备和现状基线，不是 SOP、作业指令或已批准制度。字段存在不等于现场已填写、持续执行或已有授权；文中“目标状态、建议、权限”均按 **候选 / 待确认** 处理。未修改 Excel，未新建表，不制造异常样本。

## 结论摘要

现有《质量管理与检验模板.xlsx》的 **“不合格与异常”** 已经具备一条异常闭环的主要字段：发现、工单/产品/模具/工位、数量、隔离范围、临时处理、原因、措施、恢复条件、处理结果、记录/确认人、关闭日期和状态；**“改善与审核”** 已具备较完整的原因—措施—验证—关闭字段。文件层面因此不必立即另建“异常总表”。更合适的候选方向是：以“不合格与异常”作为单件异常的主记录，只有跨批次、重复发生或需管理层追踪的事项才引用/升级到“改善与审核”，避免重复台账。

目前没有在品质 Excel 的异常工作表中发现真实已填写异常记录；现有示例行明确标注为“虚拟示例，不可用于生产”。模具《修机报告》有两行同样明确标注为“示例/已关闭”，不能当作真实运行证据。因此，是否有人实际隔离、谁能放行/恢复、原因分析和效果验证是否真的完成，均未知，不能声称已实施。

## 二、文件可证事实与现场执行未知

### 文件可证事实

1. 已有一个名为“不合格与异常”的单件异常记录入口，字段覆盖发现、范围、隔离、临时处理、原因、措施、恢复、结果、确认和关闭状态。
2. 已有“改善与审核”记录入口，能记录来源异常、原因、措施、责任人、期限、验证证据、效果验证和关闭日期。
3. 首件检查和过程巡检能记录工单、产品、标准、实测/外观结果及处理结果，可作为异常发现或效果复核的潜在证据来源。
4. 生产任务、领料核对、试模、修机报告分别具备工单、材料批次、模具/设备、隔离范围或试模结果等部分信息，但跨表共同关联键不完整。
5. 目前检查到的品质异常表没有真实业务记录；模具修机表中所见记录带有“示例”标记，不能证明实际闭环。

### 现场执行未知，不得据此补写结论

- 异常通常由谁发现、谁登记，发现后是否立即停机/停料/暂停流转。
- “隔离范围”按什么边界确定：自上次合格巡检、某材料批次、某工单、某模具/工位，还是其他依据。
- 隔离物是否有物理区域、状态标识、数量清点和防误用措施。
- 谁能判定不合格、谁能决定返工/返修/报废/让步接收，谁能批准恢复或放行。
- 原因分析是否区分临时遏制与永久措施，是否有数据、照片、样件或修机/试模证据支持。
- 恢复条件是否实际复核，恢复后首件/巡检是否完成，效果验证由谁做、看多长时间或多少件。
- 关闭日期和状态是否有人维护，关闭是否意味着产品风险已处理、措施已验证，还是仅表示任务完成。
- 现有记录是否保存在 Excel 之外的纸本、群聊、照片或其他位置；是否存在未登记异常。

## 三、质量异常全链路：目标状态、当前能力与差距

| 阶段 | 目标状态（候选 / 待确认） | 文件可见的当前能力 | 主要差距与风险 |
|---|---|---|---|
| 发现 | 发现人能依据图纸、首件、巡检、客户反馈或生产现象识别异常，并生成唯一异常编号 | 异常表有发现日期时间、编号、类别、现象；首件/巡检有结果、异常情况 | 未知谁必须登记、何时登记、异常编号如何生成；巡检/首件与异常编号未显式连接 |
| 风险控制 | 先停止扩大影响，明确是否停机、停料、暂停流转或通知管理层/客户 | 异常表有临时处理；生产任务有“上次异常” | 未见停机/升级条件、客户/交期风险字段；“临时处理”不等于已执行的控制权限 |
| 隔离 | 对受影响产品、材料、在制品和已交付风险划定范围，物理隔离、标识、清点并可追溯 | 异常表有发现时数量、隔离范围；修机报告也有停机时数量、隔离范围 | 缺批次、数量变化、隔离位置、状态标识、隔离责任人等显式连接；范围依据未知，存在混批/误用风险 |
| 原因/对策 | 区分现象、直接原因、系统/过程原因；先遏制再制定永久措施，并指定责任与期限 | 异常表有原因分析、处理措施；改善与审核有原因、措施、责任人ID、截止日期 | 字段存在但无真实记录证明深度；异常表未见责任部门/期限字段，可能依赖备注或转入改善表 |
| 恢复/放行 | 达到事先确认的恢复条件后，由有权限的人批准恢复生产/使用/放行，并记录对象和依据 | 异常表有恢复条件、处理结果、确认人、状态；首件/巡检可提供复核结果 | 未见明确“批准恢复/放行人”语义；首件/巡检没有显式异常编号、批次、模具/设备及放行结论，容易把检验结果误当授权 |
| 效果验证 | 以有效图纸/标准和适当的后续首件/巡检/客户反馈数据验证措施有效、不复发或风险受控 | 改善与审核有验证证据、效果验证；质量月报有趋势、异常/原因、措施、验证日期 | 未定义验证证据最低要求、观察窗口、重复异常判断；单件异常表本身没有独立效果验证字段 |
| 关闭 | 风险已处理、影响范围有结论、措施和效果已复核，关闭人/日期清楚；未满足则保持打开或升级改善 | 异常表有处理结果、记录/确认人、关闭日期、状态；改善与审核也有状态/关闭日期 | “确认人”和“关闭批准人”是否同一角色未知；状态值、关闭门槛、逾期升级、与改善事项的关系未确认 |

**当前能力判断：**文件结构已覆盖“记录一件异常”的大部分信息，具备小范围追溯验证的起点；尚未证明具备稳定的现场控制能力。当前最明显的风险不是缺少更多栏目，而是权限、判定口径、跨表连接和真实使用证据不足。

## 五、是否复用现有“不合格与异常”和“改善与审核”

**候选判断：可以复用，不建议立即建新异常台账。**

- **“不合格与异常”作为主记录：**一条异常一个异常编号，记录发现、风险控制、隔离范围、临时处理、原因/措施、恢复条件、处理结果和状态。首件、巡检、修机、试模等记录作为证据来源或关联对象，不重复抄成第二份异常台账。
- **“改善与审核”作为升级/改善记录：**当异常是重复发生、跨部门、客户投诉、审核不符合项、需要长期措施或需要管理层追踪时，建立/引用改善编号，在“来源异常/客户”中指向异常编号；效果验证和关闭集中在改善记录中，不把同一措施在两张表各自维护成两套状态。
- **“质量目标与月报”只做汇总和决策入口：**按确认的口径汇总重大/重复异常、趋势和资源需求，不替代异常主记录，也不把月报中的一句措施当成关闭证据。
- **需验证的边界：**是否允许单件异常直接关闭；哪些异常必须升级“改善与审核”；异常表的“关闭日期/状态”与改善表的“关闭日期/状态”谁是最终状态；两者不一致时由谁裁决。

## 六、最小验证方式（不制造样本）

**优先方式：查一条已有真实异常记录。**

1. 由总经理/品质负责人指定一条已经自然发生的真实异常，优先选择能同时找到生产任务、领料批次、首件或巡检、模具/设备或修机记录的案例；不得使用 Excel 虚拟示例，不得为了验证人为制造异常。
2. 不改 Excel，先只读核对：异常编号 → 工单/产品/版本 → 材料批次 → 模具/设备/工位 → 首件/巡检记录 → 修机/试模记录（如有） → 隔离范围和处理结果 → 恢复/放行依据 → 效果验证 → 关闭结论。
3. 对每一环只记录“找到 / 找不到 / 由其他记录补足 / 需要现场确认”，并保留原始证据位置；不把补查笔记写成正式放行凭证。
4. 由已确认的复核人判断：能否界定受影响范围、能否证明恢复依据、是否存在重复台账或状态冲突、现有字段是否足够支撑一次闭环。
5. 若当前没有可用真实异常记录：标记为 **待确认**，不制造案例；可先做桌面检查——确认是否存在纸本/照片/群聊/修机/客户反馈中的真实事件及其归档位置——仍不能将模板示例当证据。

该验证只判断“链路能否被追溯、当前记录是否支持决策”，不代表样本足以证明过程能力、异常率或制度有效性。

## 七、需总经理 / 生产 / 品质 / 运营确认的少数定义与权限

| 需确认事项 | 需要明确的最小决定 |
|---|---|
| 谁可发现并登记 | 生产、品质、模具、运营/客户反馈分别在什么情形必须登记异常；谁生成/维护异常编号 |
| 谁可立即控制风险 | 谁可以不等待批准就暂停投料、停机、暂停流转、标识和隔离；夜间/负责人不在时由谁替代 |
| 隔离边界 | 以什么作为起点（最近一次合格巡检、某工单、材料批次、模具/工位或其他）；隔离数量、位置、状态标识和记录要求由谁确认 |
| 处置决定权限 | 谁能决定返工、返修、报废、退料、让步接收或继续待判；客户要求或交期风险何时必须升级总经理/运营/客户 |
| 恢复/放行权限 | 谁能批准异常后恢复生产、解除隔离或放行产品；品质确认、生产确认、模具确认是否是不同权限，不能仅凭“处理完成”自动放行 |
| 客户/交期升级 | 何种影响范围、客户风险、交期风险或重复异常必须通知运营/客户接口和总经理；响应时限由管理层确认 |
| 关闭证据 | 关闭至少需要哪些证据：有效图纸/标准、隔离清点、原因与措施、首件/巡检复核、修机/试模记录、后续趋势或客户确认等；谁是最终关闭人 |
| 两表边界 | 什么情形只留在“不合格与异常”，什么情形必须进入“改善与审核”；来源异常编号、改善编号、两边状态不一致时谁裁决 |
| 记录与保存 | 原始记录、照片/样件、纸本、修机报告、客户往来和复核证据存放在哪里，谁可查、保存多久；不新增台账前先确认现有事实入口 |

## 八、按丰田式骨架的最小下一步（候选）

1. **目标状态 / 价值**：一条真实异常能快速止住风险、准确界定影响范围，经过有依据的恢复/放行和效果复核后才关闭；价值是防止不合格品继续流转，并让交期/客户风险可决策。
2. **当前状态**：已有“不合格与异常”和“改善与审核”字段，另有生产、批次、首件/巡检、试模/修机记录；没有真实异常样本证明这些记录已连通或按权限运行。
3. **差距与障碍**：权限和关闭门槛未确认，异常与批次/设备/首件/修机的关联键不完整，隔离范围和恢复证据可能分散，示例记录不能替代真实证据。
4. **选择合适确认方式**：先查一条已有真实异常记录；只有当关键事实不在文件中时，再针对该条记录访谈或观察实际岗位，不机械规定先现场。
5. **对策 / 实验**：经总经理及相关部门确认权限后，沿用现有两张表做一次桌面追溯核对；不改 Excel、不建新表、不制造异常、不发布 SOP。把缺口分为“已有记录可补足”“需要权限决定”“仅需最小字段/连接改进”。
6. **责任与期限**：总经理确认隔离、恢复/放行、关闭和升级边界；生产/品质/运营各指定记录提供者和复核者及期限，具体人选待确认。
7. **证据复核**：复核人对照异常、工单、材料批次、模具/设备、首件/巡检、修机/试模、隔离和恢复证据，记录实际可追溯程度及状态冲突。
