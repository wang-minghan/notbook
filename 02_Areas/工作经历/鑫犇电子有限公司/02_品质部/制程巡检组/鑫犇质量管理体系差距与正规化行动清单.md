# 鑫犇质量管理体系差距与正规化行动清单

> 目标：不为了“做一套漂亮文件”而做ISO，而是用一套小厂真正跑得动的管理骨架，把鑫犇逐步变成**大客户敢审核、订单接得住、异常查得清、人员换得动、质量能持续稳定**的供应商。

> 重要边界：本清单按 ISO 9001 质量管理体系和制造业大客户常见审核逻辑建立。具体客户还可能额外要求供应商准入、社会责任、环保、职业健康安全、信息安全、汽车行业特殊过程或客户专用表单，拿到真实客户审核清单后再逐项映射，不把假设当成客户硬要求。

## 一、执行规则

### 1. 任务状态

- `未开始`：没有负责人、表单或执行记录。
- `设计中`：流程和表单已设计，但未完成一次真实闭环。
- `试运行`：已在一个产品/模具/订单上运行，正在修正。
- `已运行`：至少连续运行一个周期，有记录、有问题、有改进。
- `已固化`：流程、表单、培训、审核和改进均已形成稳定机制。

### 2. 任务完成标准

每项任务必须同时具备：

1. 一页以内的流程规范；
2. 明确负责人和替代负责人；
3. 一张能真正填写的记录表；
4. 至少一条真实记录；
5. 发现问题后的处理记录；
6. 负责人确认可以继续执行。

**只有文件，没有真实记录，不算完成。只有记录，没有责任人和判断规则，也不算完成。**

### 3. 优先级

- **P0｜0—30天**：不做会影响大客户审核、订单接收或重大质量风险。
- **P1｜31—90天**：让体系真正运行起来，建立数据和闭环。
- **P2｜91—180天**：提高效率、稳定性、客户准入能力和数字化水平。

## 二、当前总体判断

| 模块 | 当前判断 | 主要差距 |
|---|---|---|
| 文件化框架 | 已有基础 | 手册、产品资料、部门流程已形成骨架 |
| 订单与客户要求 | 部分具备 | 缺正式评审、变更、交付确认记录 |
| 产品/图纸/材料主数据 | 正在建设 | 需要统一编码、版本、审批和现场唯一有效版本 |
| 生产与模具 | 有经验基础 | 缺稳定的批次追溯、维护周期、过程数据 |
| 检验与测量 | 有首件意识 | 缺完整检验计划、量具校准、抽样和记录闭环 |
| 不合格与客诉 | 有异常处理动作 | 缺根因分析、纠正措施、效果验证和关闭机制 |
| 供应商管理 | 尚未成体系 | 缺准入、评价、来料质量和异常追责 |
| 人员能力 | 有岗位手册框架 | 缺能力矩阵、上岗确认和培训有效性验证 |
| 内审与管理评审 | 基本缺失 | 没有定期审核、管理层评审和质量目标复盘 |
| 数据与持续改进 | 较弱 | 缺质量看板、趋势分析和改善项目台账 |

### 资料清洗和合规边界

- 岗位责任包中的“研发部、电镀车间、平车车间、装配车间”等历史部门名称，先标记为历史/待确认，不直接写入当前组织架构。
- 消防预案中的历史人员姓名只能作为历史记录，不能直接认定为现任负责人。
- 五金车间规章制度中的罚款金额、年龄限制和赔偿条款，必须由管理层、人事和必要的专业人员审核后，才能决定是否保留。

## 六、每项任务为什么存在：第一性原理说明

> 这张清单不是表格收集工程。每个任务只为解决一个真实管理问题：**让正确要求被理解、让正确过程被执行、让结果能够被证明、让异常能够被阻断、让系统能够持续变好。**
>
> 如果某项任务在鑫犇的实际场景中既不降低风险、又不支持决策、也不产生有用证据，应删掉或合并。不要为了“看起来像大公司”而增加流程。

### P0：防止错误订单、错误生产和错误交付

| ID | 任务意义（第一性原理） |
|---|---|
| P0-01 | **责任必须有归属。** 没有明确负责人，异常只能靠老板临时救火，流程无法稳定运行。 |
| P0-02 | **没有目标就无法判断好坏。** 质量目标把“做好质量”变成可判断的经营结果。 |
| P0-03 | **问题必须进入固定决策场景。** 质量例会让问题从个人记忆进入公司共同决策，并形成期限和责任。 |
| P0-04 | **风险必须在扩大前被升级。** 规定停机、隔离和通知条件，避免小异常变成批量报废或客户投诉。 |
| P0-05 | **接单前解决不可交付问题。** 订单评审的本质是确认“客户要求”和“公司能力”是否匹配，而不是接单后再补救。 |
| P0-06 | **客户要求不能只存在某个人脑中。** 集中记录质量、包装、标签和交付要求，防止遗漏和人员变动造成失控。 |
| P0-07 | **变更是质量风险的主要入口。** 任何图纸或技术变更都必须知道改了什么、何时生效、谁批准，避免新旧要求混用。 |
| P0-08 | **交付是最后一次放行。** 出货前确认数量、批次、标签和资料，防止内部做对了但交付错了。 |
| P0-09 | **产品必须有唯一身份。** 主数据把客户、型号、图号、版本、材料和模具连起来，防止“同名不同物”。 |
| P0-10 | **材料错误会从源头污染整批产品。** 对照表和批次记录把材料选择从经验判断变成可核对事实。 |
| P0-11 | **文件必须有唯一有效版本。** 版本清单解决“现场到底该看哪份”的问题。 |
| P0-12 | **旧版本必须退出现场。** 只发布新版本而不回收旧版本，等于同时保留两套标准。 |
| P0-13 | **记录必须可找、可证、可复盘。** 保存规则避免记录丢失，也避免无期限堆积造成管理负担。 |
| P0-14 | **开工前阻断错误。** 生产任务确认把产品、材料、模具、设备和交期一次性对齐，降低返工成本。 |
| P0-15 | **首件是批量生产的闸门。** 先证明第一件正确，再允许复制，避免把错误放大成整批错误。 |
| P0-16 | **过程会漂移，不能只检第一件。** 巡检用于尽早发现毛刺、尺寸和送料状态变化，缩小影响范围。 |
| P0-17 | **问题必须能反向定位。** 批次追溯让公司知道哪些材料、模具、设备和人员可能受影响，从而做到精准隔离。 |
| P0-18 | **现场必须一眼区分状态。** 合格、待判、不合格混在一起时，任何后续流程都可能误用。 |
| P0-19 | **不合格品必须物理隔离。** 仅在表格里标记而不隔离，无法阻止误发、误用和混批。 |
| P0-20 | **异常处理必须从止血走到根因。** 临时修好不等于问题解决，必须验证永久措施有效。 |
| P0-21 | **客诉响应速度影响客户信任。** 先快速控制影响，再查原因和给出措施，避免客户等待和风险扩散。 |
| P0-22 | **重复异常说明系统没有真正解决问题。** 台账用于识别模式，把零散故障升级为改善项目。 |
| P0-23 | **测量工具也可能出错。** 量具台账确保知道有什么工具、在哪里、是否可用。 |
| P0-24 | **错误测量会制造错误放行。** 校准/检定控制测量可信度，避免“数据看起来合格”但依据本身不可靠。 |
| P0-25 | **检验结论必须可复核。** 统一记录标准、实测值和检验人，避免只留下“合格”两个无法验证的字。 |

### P1：把一次性控制变成稳定的管理系统

| ID | 任务意义（第一性原理） |
|---|---|
| P1-01 | **供应商是质量链的一部分。** 先知道从谁采购、出了问题找谁，才能控制外部输入。 |
| P1-02 | **低价不等于低总成本。** 评价供应商的质量、交期和异常响应，避免采购节省的钱被返工和停线吃掉。 |
| P1-03 | **来料质量要在进入生产前确认。** 越早发现问题，隔离和退换成本越低。 |
| P1-04 | **材料证明必须和实际使用批次关联。** 否则证明文件无法证明这批材料到底去了哪里。 |
| P1-05 | **外部异常必须推动对方改进。** 供应商纠正措施防止同一个问题反复回到工厂。 |
| P1-06 | **模具需要生命周期管理。** 履历让维修、寿命和质量问题可以关联，而不是靠老师傅记忆。 |
| P1-07 | **预防性维护比故障后抢修便宜。** 在可控时间维护，减少突然停机和批量质量风险。 |
| P1-08 | **设备状态直接影响过程稳定性。** 点检和保养把“设备突然坏”变成可提前发现的风险。 |
| P1-09 | **关键备件短缺会放大停机损失。** 最低库存让备件管理与生产风险相匹配。 |
| P1-10 | **维修后必须证明恢复正确。** 试模和恢复确认防止“修完能动但产品不合格”。 |
| P1-11 | **每个重点产品需要一张控制地图。** 质量控制计划明确每道工序控制什么、怎么控制、谁控制。 |
| P1-12 | **不是所有尺寸风险相同。** 识别关键特性，把有限检验资源集中到真正影响客户的地方。 |
| P1-13 | **趋势比单个合格点更早暴露问题。** 不良趋势能在超差前提醒调整。 |
| P1-14 | **测量方法本身要可信。** 同一产品不同人测出不同结果时，数据不能支持决策。 |
| P1-15 | **交付资料是客户使用和追溯的接口。** 确保客户拿到的不只是货，还有必要的证明和识别信息。 |
| P1-16 | **岗位能力必须可见。** 能力矩阵让公司知道谁能独立做、谁需要带教、哪里没有替代人。 |
| P1-17 | **不能让单个人成为瓶颈。** 替代人机制降低请假、离职和突发缺人的经营风险。 |
| P1-18 | **培训必须证明会做，而不是来过。** 实际演示和结果确认才说明能力转移成功。 |
| P1-19 | **流程变了，能力也要同步更新。** 变更后的再培训防止员工继续按旧方法执行。 |
| P1-20 | **基础错误应在上岗前被发现。** 考核让图纸、材料、模具和异常处理的关键知识可验证。 |
| P1-21 | **没有审核就不知道体系是否真实运行。** 年度内审提供系统性检查，而不是等客户发现问题。 |
| P1-22 | **审核必须检查真实业务链。** 用真实订单和记录审核，才能发现文件与现场之间的断点。 |
| P1-23 | **发现问题只是开始。** 不符合项整改和验证确保问题被关闭，而不是换一种写法隐藏。 |
| P1-24 | **管理层必须定期看系统结果。** 管理评审决定资源、目标和优先级，避免质量责任只落在现场。 |
| P1-25 | **改进必须有目标和证据。** 改善台账让公司知道投入换来了什么结果，避免“忙了但没变好”。 |

### P2：把“能生产”升级为“值得大客户长期合作”

| ID | 任务意义（第一性原理） |
|---|---|
| P2-01 | **客户先判断供应商是否基本可信。** 公司资料包缩短准入审核和信息反复确认。 |
| P2-02 | **质量能力必须能被外部验证。** 质量资料包把目标、控制、设备和审核证据组织成客户能审的结构。 |
| P2-03 | **样件交付要证明过程可复制。** 首件资料把图纸、材料、测量和结果连成完整证据链。 |
| P2-04 | **审核整改能力决定客户是否继续给机会。** 整改资料包证明问题能被识别、解决和防止复发。 |
| P2-05 | **不同客户的要求不能混用。** 特殊要求清单避免把A客户规则错误应用到B客户。 |
| P2-06 | **交期是客户价值的一部分。** 交期数据让公司知道延期发生在哪里，而不是只在客户催货时被动反应。 |
| P2-07 | **接单承诺必须基于能力。** 产能和瓶颈清单防止为了拿订单做出无法兑现的承诺。 |
| P2-08 | **报价也是风险决策。** 接单前评估材料、模具、设备、交期和质量难度，避免“订单越多亏得越多”。 |
| P2-09 | **风险要按重要性排序。** 关键客户、产品和材料清单帮助有限资源先保护高损失环节。 |
| P2-10 | **不能让单点故障摧毁交付。** 业务连续性预案降低停电、设备、材料和人员中断造成的失约风险。 |
| P2-11 | **数据要能互相连接。** 统一数据表让产品、材料、模具、版本、批次和异常形成可查询的经营事实。 |
| P2-12 | **一件事只能有一个事实入口。** 唯一编号避免重复表格互相矛盾，减少寻找和对账成本。 |
| P2-13 | **数据丢失等于管理记忆丢失。** 权限、备份和恢复测试保证关键经营证据可持续使用。 |
| P2-14 | **管理层需要看到趋势而不是零散记录。** 质量看板把记录转化为资源和改善决策。 |
| P2-15 | **数字化必须先证明实际价值。** 选一个产品/模具跑通全链路，验证系统能解决问题后再扩展，避免做大而空的平台。 |

## 七、建议先做的“最小可运行系统”

不要一上来把所有制度做满。第一阶段只选一个真实产品、一个真实模具、一个真实订单，跑通以下链路：

```text
客户订单/图纸
→ 订单评审
→ 产品与材料确认
→ 模具确认
→ 生产任务
→ 首件检查
→ 过程巡检
→ 批次追溯
→ 异常隔离
→ 纠正措施
→ 完工/出货确认
→ 客户反馈
→ 月度复盘
```

只要这条链路能留下完整证据，体系就开始从“手册”变成“管理系统”。

## 八、什么时候算“准备好接大客户”

至少满足以下条件，再把自己定位为“客户审核准备就绪”：

- 能在30分钟内拿出一个订单的完整资料链；
- 能从成品追到材料批次、图纸版本、模具、设备和检验记录；
- 任意一个不合格品都有状态标识和处置结论；
- 任意一次客诉都有原因、措施和效果验证；
- 关键量具在有效校准期内；
- 现场只使用有效版本的图纸和表单；
- 关键岗位有培训记录和替代人；
- 最近至少完成一次内部审核和一次管理评审；
- 质量、交付、客诉和异常数据能用表格或看板说清楚；
- 所有记录都能找到责任人，而不是“问老板才知道”。

## 九、管理层必须先拍板的事项

以下内容不能由整理文档的人自行猜测：

- 谁是质量负责人；
- 谁批准图纸、工艺和技术变更；
- 谁能放行首件和不合格品；
- 谁负责客户投诉和交付承诺；
- 记录保存多久；
- 哪些产品/尺寸属于关键特性；
- 哪些供应商必须评价；
- 哪些表单必须执行，哪些只是参考；
- 质量目标和异常升级的红线是什么。

## 十、第一周行动安排

- [ ] 召开一次30分钟管理层会议，确认质量负责人和四个流程负责人。
- [ ] 选定一个正在生产的真实产品和一个真实订单作为试点。
- [ ] 盘点现有图纸、材料、模具、量具、表单和客户要求。
- [ ] 建立P0-05、P0-14、P0-15、P0-19、P0-20五张核心表单。
- [ ] 现场跑一次“订单—生产—首件—异常—完工”闭环。
- [ ] 把发现的问题登记到《差距与改进台账》，不靠口头记忆。
- [ ] 一周后复盘：哪些步骤没人执行、哪些字段没人填、哪些责任人不明确。

## 十一、禁止事项

- 不要为了审核伪造历史记录。
- 不要先写一百页制度，再想办法让现场执行。
- 不要把“员工签字”当成培训有效性。
- 不要把“检验合格”当成没有测量依据。
- 不要让同一个产品同时存在多个未标版本。
- 不要把客户口头要求只存在某个人微信里。
- 不要把所有异常归因于“员工粗心”或“模具问题”，必须追到可控制的根因。
