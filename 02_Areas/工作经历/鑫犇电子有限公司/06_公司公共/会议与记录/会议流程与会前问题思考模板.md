# 会议流程与会前问题思考模板

> **定位：拟建立、待确认。** 本说明只配套现有《会议问题跟踪表.xlsx》，不新增治理表、不替代各部门业务记录，也不表示本流程已经正式实施。

## 一、采用丰田式骨架，但不把所有事项套成同一顺序

本模板借鉴丰田类书籍中可直接使用的管理骨架，再按鑫犇规模压缩：

> **目标状态／要解决的结果 → 当前状态 → 差距与障碍 → 现场或记录确认 → 先采取合适的对策 → 明确责任与期限 → 用证据复核 → 固化或继续改善**

“现场确认”是重要手段，但不是所有事项的第一步。不同问题采用不同入口：

- **已发生的异常**：先控制质量、安全、交付风险，再到现场确认事实和影响。
- **重复发生的问题**：先对照目标状态和现行标准，再现场观察实际做法，寻找障碍和原因。
- **计划、交期或资源事项**：先确认客户/订单目标、当前状态和约束，再决定责任、资源与期限。
- **标准化事项**：先确认当前最好做法和实际使用者，再形成一页标准并验证是否有效。
- **改善提案**：先说明目标状态、现状差距和下一步实验，不要求一次性找出“最终根因”。

这保留了丰田的“目标—现状—差距—下一步—复盘”骨架，同时只保留鑫犇真正需要的记录。具体会议频率、权限和标准生效方式仍须确认。

## 二、会前：先提问题，不带空泛议题

会前由发现问题的人准备一条“可确认、可处理”的问题。必备信息：

- **发生在哪里、什么时候发现**：部门／车间／工序／设备／订单等。
- **事实是什么**：现象、数量、批次、影响；能附照片、记录或样品更好。
- **希望会议决定什么**：谁处理、何时完成、需要谁协同。
- **问题分类**（可多选，但只在跟踪表中保留一条问题）：
  - 人员：缺员、不会做、培训、纪律、岗位能力。
  - 设备：故障、点检、维修、安全隐患、产能。
  - 材料：缺料、错料、来料、库存、批次、供应商。
  - 质量：不良、首件、巡检、客诉、隔离、检验标准。
  - 交期：订单、排产、进度、延期、交付协调。
  - 管理：流程不清、责任不明、信息断点、重复发生、跨部门协同。
- **会前不能确认的内容**：先写“待现场确认”，不要凭猜测定责或定方案。

### 会前快速思考

```text
问题：
分类：人员／设备／材料／质量／交期／管理
事实与影响：
现场要确认什么：
希望会议决定：责任人、协同人、期限、完成证据
```

## 三、会议中：围绕目标状态和下一步，不把会议开成泛泛汇报

每个事项先判断属于哪一种入口，再只推进必要内容：

1. **目标状态**：要达到什么结果，为什么重要（客户、质量、交期、安全、成本或人员能力）。
2. **当前状态**：已经发生了什么，现有记录、实物或数据是什么。
3. **差距与障碍**：差距在哪里，当前卡点是什么；不能确认的内容标为“待确认”。
4. **选择合适的动作**：异常先控制风险；重复问题做原因验证；计划事项补资源；标准事项形成一页当前标准。
5. **明确责任和期限**：只能有一名“谁负责”；协同人写在另一列；动作必须写成可验收结果。
6. **明确验证证据**：提前约定用什么证明有效，如检查记录、培训表、保单、检查表、整改照片、检验记录或现场结果。

会议不要求每个事项都完成完整的原因分析；先把风险控制住、下一步做对，并在复盘时根据证据继续调整。没有形成“责任人＋期限＋证据”的事项，不作为已决定事项。

## 四、会后：只填现有8列跟踪表

会议结束后，将决定事项录入《会议问题跟踪表.xlsx》，**不另建会议问题表**。一行一个问题／决定，使用现有8列：

| 列名 | 填写规则 |
|---|---|
| 编号 | 一次会议一个编号，保持唯一、连续可追溯。 |
| 问题 | 写会上确认的问题和要达到的结果，避免写成口号。 |
| 谁负责 | 只填一名直接负责人；负责人对完成结果负责。 |
| 协同人 | 填实际提供支持的人员、班组或部门。 |
| 完成期限 | 填具体日期；周期性事项写明每天／每周等周期。 |
| 完成证据 | 写关闭时要看到的一句话证据；未完成时可先写拟提供证据。 |
| 状态 | 使用现有状态；至少区分“未开始、进行中、已完成、逾期”（具体下拉值待确认）。 |
| 备注 | 记录现场确认结果、变更原因、阻塞点或升级情况；不代替其他业务记录。 |

> **原则：表中只记录需要跟踪的决定事项。** 普通汇报、已解决事项和没有行动要求的讨论不必占一行。

## 五、每周复盘：只看未完成项

拟按周查看跟踪表，**只筛选“未开始／进行中／逾期”等未完成项**：

- 谁负责：负责人逐项说明事实进度，不作泛泛汇报。
- 到期未完成：说明原因、当前阻塞、新的明确期限和证据；必要时改为“逾期”。
- 已完成项：有关闭证据后再改为“已完成”，不在周会上反复展开。
- 重复发生的问题：在备注中标明“重复发生”，决定是否另行分析根因；不因此新增复杂台账。

## 六、总经理现场验收与关闭

- 对重要、反复发生、影响质量／交期／安全的事项，拟由**总经理现场验收**，而不是只听口头汇报。
- 验收重点：现场结果是否达到决定要求，证据是否真实、可追溯，相关人员是否知道新要求。
- 验收通过：补齐“完成证据”，状态改为“已完成”。
- 验收不通过：状态保持“进行中”或改为“逾期”，在备注写明差距、责任人和新期限。
- “已完成”不等于永久不再发生；若再次发生，按新问题重新编号并记录。

## 七、升级规则（拟建立／待确认）

出现以下任一情况，负责人应在备注中标明“需升级”，并提交总经理决定：

1. 到期仍未完成，且没有可信的完成计划；
2. 连续两次周复盘仍未完成，或同一问题重复发生；
3. 涉及人员安全、重大质量风险、客户交期或停产风险；
4. 责任人、协同资源或跨部门权限不足，现场无法推进；
5. 需要改变标准、投入费用、调整排产或改变部门职责。

升级时仍只使用原跟踪表：补充事实、影响、卡点、建议期限和所需决定，不另建升级表。升级后的决定继续回填同一行；如形成全新问题，再新建编号。

## 八、使用边界

- 本模板是现有会议问题跟踪表的填写说明，不是正式制度。
- 组织、部门和岗位归属以《鑫犇公司文件树.md》及其指定的受控组织架构资料为准。
- 频率、状态值、总经理验收范围和升级权限均为**待确认**事项；确认前按实际会议决定执行并在备注中留下说明。
