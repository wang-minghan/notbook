# 精益管理原则与部门落地路线

> 本页是公司治理资料入口下的轻量说明，不是新的制度、SOP或考核办法。内容结合《丰田生产方式》《丰田模式：精益制造的14项管理原则》《精益思想》（白金版）和《丰田套路》提炼，按鑫犇50多人小工厂的规模做了简化。

## 一、使用边界

- **现行事实**：现有组织、资料归属和治理边界以[[../../鑫犇公司文件树]]、`restructure_spec_v2.md`及公司正式受控文件为准。当前正式组织单元包括生产部、品质部、运营部、行政部、财务部；生产部含工程技术组、清洗车间、生产车间、模具维修组，品质部含制程巡检组、成品出货检验组，运营部含业务组、采购组、仓储组。
- **拟建立机制**：本文提出一套先从订单、生产、质量和异常入手的轻量改善节奏，需经公司确认后试运行，不视为已经实施。
- **待确认事项**：实际岗位人员、班组长设置、产能与交期口径、质量放行权限、会议频率、指标基线、记录保存位置和改善提案的批准权限，均不能由本页推定。
- 不新增“精益管理部”、新的顶层目录、复杂RACI或多层治理。原则上沿用现有部门和[[../../鑫犇公司文件树]]规定的资料归属；跨部门记录进入`06_公司公共`，废止版本进入`99_归档`。

## 二、适合鑫犇的十项原则

| 原则 | 对50多人小工厂的实际含义 | 不做什么 |
|---|---|---|
| 1. 以客户价值和订单交付为起点 | 先弄清客户要求、图纸版本、数量、质量和交期，再安排资源；减少等待、返工和错误承诺 | 不把“忙”“产量高”当作价值，不为做报表而做报表 |
| 2. 让流程连续、减少停滞 | 沿“订单—计划—物料—生产—检验—出货”观察交接，优先消除最常见的等待和返工 | 不一开始就铺开全厂流程或购买复杂系统 |
| 3. 按需求拉动，控制在制品 | 以已确认订单和现场实际能力安排生产；小批验证、及时转序，避免盲目提前生产和堆积 | 不把大批量生产、库存增加误认为效率 |
| 4. 标准作业先于改善 | 对关键产品、首件、换模、检验、异常处理先形成当前可执行的简明标准，并标明版本 | 不把未经确认的建议写成既成SOP |
| 5. 质量在源头内建 | 操作者和制程巡检尽早发现、隔离、记录；异常先停在现场，不让问题流到下工序或客户 | 不把所有质量责任推给品质部，也不以末端挑选替代过程控制 |
| 6. 异常可视、及时升级 | 用现场能看懂的状态、异常记录和短会暴露问题；规定谁发现、谁先处置、何时升级待确认 | 不追求漂亮看板，不把红灯变成追责工具 |
| 7. 到现场看事实，用数据验证 | 主管到生产车间、清洗车间、模具维修组、仓储组看实物、记录和流转，先问“发生了什么”再定措施 | 不只在会议室凭印象判断，也不为收集数据增加无用填报 |
| 8. 小步PDCA和反复追因 | 选一个真实问题，明确现象、临时措施、原因假设、验证结果和下一步；优先处理重复发生的问题 | 不同时启动大量项目，不用“加强管理”作为结论 |
| 9. 尊重并培养一线能力 | 让实际操作人员参与标准、异常和改善；通过岗位与培训资料使关键经验可交接 | 不把改善变成少数管理人员的额外运动 |
| 10. 管理者以身作则、长期坚持 | 总经理及部门负责人保持短周期跟进，关注交付、质量、异常关闭和能力，而非只看一次性成果 | 不把90天路线当成一次性运动或照搬丰田组织、术语和工具 |

## 四、90天分阶段路线（仅作为拟建立机制）

### 第1阶段：确认与选点（第1—30天）

**目标**：不急于推广，先确认事实和一个端到端试点。

- 确认现行组织、岗位接口、质量放行、异常升级和资料存放位置；未确认内容列入`notes/35_待确认事项清单.md`。
- 由管理层选一个真实订单链或一个重复质量/交付问题作为试点；试点应能覆盖至少两个部门，但不要求全公司同时参加。
- 到现场核对订单版本、生产任务、物料/模具状态、检验记录和异常事实，画出不超过一页的当前流程。
- 设定不超过4个观察指标，并记录初始基线；指标定义、责任人和频率待公司确认。
- **阶段输出（拟）**：试点范围、当前事实清单、问题优先级、指标基线、待确认事项。不得把输出当成已批准制度。

### 第2阶段：小范围试运行（第31—60天）

**目标**：在一个试点内形成“发现—处置—记录—验证”的短闭环。

- 对试点工序建立一页式当前标准：输入、关键步骤、质量点、异常时先做什么、何时升级。
- 采用现场可见的简单状态标识或共享记录，追踪订单/任务处于待生产、生产中、待检、异常或完成中的哪一状态。
- 每周进行一次短复盘，只处理少量高影响问题；每项问题必须有事实、临时措施、负责人、期限和验证结果。
- 让一线人员参与修改标准，行政部/人事组记录必要的培训或授权证据；不新增复杂审批链。
- **阶段输出（拟）**：试点标准初稿、异常闭环记录、培训/能力记录、首轮指标变化和未解决问题清单。

### 第3阶段：复盘与固化（第61—90天）

**目标**：判断哪些机制值得保留，再决定是否扩展到相邻流程。

- 管理层复盘试点是否改善了交付、质量、等待、返工或异常关闭；同时检查是否增加了无效记录和现场负担。
- 对有效做法进行版本化，分别归入已有部门文件、公司公共模板/会议记录或治理说明；无效做法停止，不为凑成果保留。
- 仅在试点证据足够且相关部门同意后，扩展到一个相邻环节，例如“采购—验收—入库”或“模具维修—试模—生产恢复”。
- 将后续事项纳入现有经营会议、管理评审和PDCA闭环，不成立新的精益治理层。
- **阶段输出（拟）**：试点复盘、是否扩展的决定、修订后的受控文件清单、下一周期改善主题。扩展范围和正式生效日待确认。

## 五、轻量运行规则

1. **一个问题一个记录入口**：优先使用现有异常、会议、整改或部门记录；不并行制造多套台账。
2. **一个试点一组指标**：先看交付、质量、异常关闭和关键资源影响，指标定义经确认后再长期使用。
3. **一个标准一个版本**：试行稿、现行稿和废止稿必须能区分，文件控制沿用治理体系要求。
4. **先现场事实，后会议结论**：会议只决定责任、期限、资源和验证方式；不替代现场判断。
5. **改善不等于加人加表**：任何新增记录都要说明它帮助发现什么问题、由谁使用、多久复核；没有用途就不新增。
6. **异常先控制交付和质量风险**：必要时先隔离、暂停或升级，责任归属和根因分析随后完成；具体停线、放行和赔付权限以正式授权为准。

## 六、待确认事项

- 试点选哪一类产品、工序或订单，试点负责人是谁；
- 生产任务状态由谁维护、多久更新、使用纸面还是现有电子文件；
- 生产部、品质部、运营部在异常暂停、恢复和质量放行上的实际权限；
- 订单交期、一次合格、返工、不良、异常关闭等指标的正式定义和数据来源；
- 采购、仓储、品质对关键材料到货验收、隔离和入库的现实分工；
- 模具、设备、量具的实际责任人和维修后确认要求；
- 现场短会、经营会议、管理评审的频率、参加人和纪要归档位置；
- 试点记录是否纳入现有表单、模板和质量管理系统模板；
- 90天后是否扩展、由谁批准扩展，以及正式文件的生效日期。

## 七、参考思想的取舍

- **《丰田生产方式》**：吸收消除浪费、准时化、自动化/异常停止、标准作业和持续改善；不照搬大规模制造环境下的工具密度。
- **《丰田模式：精益制造的14项管理原则》**：吸收长期主义、连续流、拉动、标准化、现场管理、培养人员和反复反思；按鑫犇规模压缩为少数可执行机制。
- **《精益思想》（白金版）**：吸收价值、价值流、流动、拉动、尽善尽美五个方向；优先从一个价值流试点，不制作全厂复杂价值流图。
- **《丰田套路》**：吸收以目标状态、现状、障碍、下一步和复盘为核心的教练式改善；要求管理者带着问题到现场，不把提问套路化为考核。

> **结论**：鑫犇现阶段最值得建立的不是一套“精益部门”或大量工具，而是一个小范围、可看见、能关闭的改善循环：明确客户/订单要求 → 现场暴露问题 → 先控制风险 → 找到可验证的原因 → 由实际执行者参与改进 → 用现有文件和会议机制固化。
