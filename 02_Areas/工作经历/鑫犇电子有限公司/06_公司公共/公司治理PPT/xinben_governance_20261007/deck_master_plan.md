# 鑫犇电子公司治理与部门协同管理体系 V3 — Deck Master Plan

> Purpose: project-wide execution and acceptance anchor for the 36-page deck.
> Status: derived from `restructure_spec_v2.md`, `design_spec.md`, `spec_lock.md`, and the current V3 page roster. This file is an execution/audit contract; it does not silently change confirmed facts, authority, KPI values, or page content.
>
> Hard rule: a page is not complete because its SVG is valid or its PPTX exports. It is complete only when core message, semantic visual grammar, responsibility/decision paths, resource plan, and page-level acceptance checks are all satisfied.

## 1. Deck-wide contract

- Audience: management team, department heads, customers and partners.
- Canvas: 1280×720, 16:9.
- Narrative: governance boundary → authority → collaboration processes → management control → review/improvement → landing.
- Current locked color semantics remain authoritative: blue = customer input/main route/structure; teal = collaboration/record/closure; orange = authorization/decision; purple = professional judgement/quality/engineering; red = abnormality/escalation; yellow = risk/pending confirmation.
- Visual language: formal governance system with varied semantic diagrams; do not use one generic horizontal card chain as a substitute for trees, matrices, swimlanes, decision flows, loops, roadmaps, or evidence chains.
- Image policy: current project has no confirmed mandatory photo/AI image set. Existing diagrammatic visuals, icons, and deliberate whitespace are valid visual anchors. Any new external/AI image requires a resource row with purpose, composition, source, status, and placement before use.
- Formula policy: no formula-heavy page is currently identified. If a formula appears, register it through the formula manifest and formula rendering workflow; do not place untracked raster math.

## 3. Resource and review gates

For every page before export:

- [ ] Core message is one assertion sentence.
- [ ] Page role and visual grammar match the content.
- [ ] Decision, exception, responsibility, evidence, and loop relations are shown where applicable.
- [ ] Any image/icon/diagram resource has a purpose and placement; no decorative image is used as a substitute for structure.
- [ ] No unconfirmed authority, KPI value, certification, or implemented system is implied.
- [ ] Page rhythm (`breathing`, `anchor`, `dense`) is visible and not flattened into the same card layout.
- [ ] Current SVG has been checked against the page's non-negotiable acceptance item.

Final acceptance is three separate results:

1. Technical: project validation, workflow gate, SVG quality checker, export/read-back.
2. Structural: 36-page roster, page-role/grammar match, responsibility/decision/evidence paths.
3. Visual: rendered page-by-page review for hierarchy, whitespace, rhythm, composition, and semantic clarity.

A failure in any one category must be reported as incomplete; it cannot be hidden by passing another category.
